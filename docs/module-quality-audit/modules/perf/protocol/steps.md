## Step 2 Threat and failure model

This module writes only to a process-internal `Map` and, when flushed, to `process.stderr` via the default writer at `packages/ax-code/src/perf/native.ts:163`. There is no network, filesystem, or database surface, and no secret-shaped input is persisted — the `input`/`output` byte accounting at `:66-67` stores only integer sizes, never the payload contents. The failure mode of note is the `process.on("exit", ...)` listener registered at `:172`: a native-addon crash cannot be caught in JS, so an exit-time flush can be lost on a hard SIGKILL or native abort, which the surrounding codebase already acknowledges in `src/flag/flag.ts:124-127` for `AX_CODE_DEBUG_ENGINE_NATIVE_SCAN`. Re-throw semantics in `run`/`runAsync` (`:89-92`, `:106-109`) preserve the caller's error contract, so the profiler cannot mask a real failure. No untrusted input crosses the module boundary: every `name` and `input` argument originates from first-party call sites listed in Step 1.

## Step 3 Correctness

`run` at `packages/ax-code/src/perf/native.ts:80-93` correctly short-circuits when disabled (`:81`), times only the synchronous body, records on both success (`:87`) and failure (`:90`), and re-throws on error (`:91`) — error path is sound. `runAsync` at `:97-110` mirrors this with `await fn()` so the timer captures the resolved work, not just promise construction; the inline comment at `:95-96` documents why a separate variant exists. The aggregation math in `record` (`:52-69`) is integer-additive over a get-then-set pair with no `await` between them, so Node's single-threaded event loop makes the update atomic per name; concurrent `runAsync` calls sharing a `name` cannot lose updates. `snapshot` at `:112-140` derives `avgMs` with a zero-guard (`:117`) and sorts descending by `totalMs`. One correctness caveat: `avgMs` in `snapshot` is recomputed but the per-row `maxMs` is stored at `:65` via `Math.max` — both are consistent. The `bytes()` helper at `:33-50` returns 0 for functions/symbols (no branch) and 0 on `JSON.stringify` throw (`:45-47`), so a circular `input`/`output` degrades gracefully to zero rather than crashing the profiled call.

## Step 4 Performance

Two real concerns, both observer-effect shaped. (a) `bytes()` at `packages/ax-code/src/perf/native.ts:43-44` runs `Buffer.byteLength(JSON.stringify(value))` on every object-typed `input`/`output` while the timer is conceptually associated with the wrapped call — but `record` is invoked AFTER `performance.now() - start` is computed (`:87`, `:90`, `:104`, `:107`), so the serialization cost does NOT inflate `totalMs`/`avgMs`. Good. However it DOES inflate wall-clock latency of every profiled dispatch, which on hot paths like `src/code-intelligence/native-store.ts:50` (per-symbol `index.${name}`) and `src/file/ignore.ts:33` (`fs.isIgnored`, called once per walked file) can dominate. (b) `render` at `:142` uses a default parameter `value = NativePerf.snapshot()`, so calling `render()` with no arg materializes the full snapshot even when profiling is disabled — only to early-return at `:143`. Both are Medium at most because the whole subsystem is gated behind `AX_CODE_PROFILE_NATIVE` (off by default per `src/flag/flag.ts:268`). No N+1, no unbounded growth in the hot non-profiled path.

## Step 5 Design and ownership

The namespace-export pattern (`export namespace NativePerf` at `packages/ax-code/src/perf/native.ts:75`) matches the codebase convention noted in `AGENTS.md` ("core code uses TS namespaces heavily"). The `Stat`/`Row`/`NativePerfSnapshot` type layering at `:4-27` is minimal and well-factored: `Row` extends `Stat` with derived `avgMs` and adds `name`, which `snapshot` populates. `install`/`enable`/`flush`/`reset` form a coherent lifecycle API, with `install` idempotent via the `ready` guard at `:170`. One design smell: `ready` is set but never cleared, so `reset()` at `:182` clears stats but cannot reset the lifecycle — once `install()` has fired, the `process.on("exit")` listener is permanent for the process. This is acceptable for a CLI process but would be a leak in an embedded long-lived host (e.g. the desktop Electron renderer reuse path). Coupling is intentionally narrow: the module imports only `Flag` (`:1`) and `FeatureFlag` (`:2`), both first-party, and is imported by 15+ sibling modules — a clean dependency direction with no cycles.

## Step 6 Hygiene and dead code

No empty catches that swallow errors silently — the one `try/catch` at `packages/ax-code/src/perf/native.ts:43-47` deliberately returns 0 because byte-size accounting must never throw into a profiled hot path, and this is the correct disposition for a best-effort metric. No TODOs, no commented-out blocks, no unreachable branches. The `formatMs` helper at `:71-73` is used exactly twice (`:150`, `:157`) — appropriately small. The `Row` type's `avgMs` is computed in `snapshot` rather than stored, avoiding stale averages — good hygiene. The default-parameter pattern at `:142` (`value = NativePerf.snapshot()`) is mildly wasteful (see Step 4) but not dead. Exports are all referenced by downstream consumers (Step 1 grep), so there is no orphaned surface. The `bytes()` recursion strategy mixes per-item recursion for arrays (`:41`) with whole-object `JSON.stringify` for objects (`:44`); this is inconsistent but not incorrect, and consolidating it would add complexity without measurable benefit.
