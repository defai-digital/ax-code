## Step 1 — Map

The preload unit is a single file `desktop/packages/electron/src/preload.js` (74 LOC) that runs in the renderer process with Node integration disabled but `contextBridge`/`ipcRenderer` available (the Electron preload isolation model). It exposes three globals to the renderer via `contextBridge.exposeInMainWorld`: `__AX_CODE_DESKTOP_ELECTRON__` (preload.js:33-37) carrying a `runtime: "electron"` marker and a `recordStartupEvent(name, details)` method that invokes the `desktop_record_startup_event` IPC handler; `__AX_CODE_DESKTOP_DESKTOP_BOOT_OUTCOME__` (42) created via `createElectronDesktopBootOutcome()` from `./desktop-boot-outcome`; and `__TAURI__` (48-74), a Tauri-compatible shim so the shared UI package (`@openchamber/ui`) works in both Tauri and Electron without code changes. The shim exposes `core.invoke(command, args)` (50-55) gated by `isAllowedDesktopInvokeCommand` from `./preload-ipc-policy`, `dialog.open(options)` (57-59) mapping to `desktop_dialog_open`, and `event.listen(channel, handler)` (64-73) for openchamber-namespaced event subscriptions. A fourth concern is the main→renderer event bridge: `ipcRenderer.on("ax-code:dom-event", ...)` (13-21) re-dispatches main-process envelopes as DOM `CustomEvent`s on `window`, scoped to the `openchamber:` namespace.

## Step 2 — Threat model

The preload script is the _only_ privileged bridge between the untrusted renderer (web content) and the trusted main process — every capability the renderer can exercise is defined here. The dominant boundary is the IPC invoke allowlist: `core.invoke` calls `isAllowedDesktopInvokeCommand(command)` (preload.js:51) and rejects unknown commands with `Promise.reject(new Error("Desktop IPC command is not available"))` (52) before reaching `ipcRenderer.invoke`. This composes with the `DESKTOP_INVOKE_COMMANDS` Set in `preload-ipc-policy.js` (reviewed in the desktop-electron-security unit) to make the surface fail-closed — a renderer cannot reach an unlisted main-process handler. The second boundary is event-channel scoping: `event.listen(channel, handler)` rejects any channel not starting with `openchamber:` (preload.js:66-68, returning a no-op unlisten), and the `ax-code:dom-event` bridge ignores envelopes whose `payload.event` does not start with `openchamber:` (15) — so the renderer cannot subscribe to arbitrary main-process channels nor be fed arbitrary event names. The third boundary is the `{ once: true }` listener for `openchamber:app-ready` (preload.js:28) which signals main once and auto-removes, preventing repeated `ax-code:renderer-app-ready` signals. The `dialog.open` passthrough (58) is unscoped but maps only to `desktop_dialog_open`, which has its own main-process-side validation.

## Step 3 — Correctness

Observed invariants: (1) IPC is fail-closed — `isAllowedDesktopInvokeCommand` returns false for non-strings or unknown commands (preload-ipc-policy.js:62-64), and the preload rejects before invoking (preload.js:51-53); (2) event channel scoping is enforced on both directions — inbound `ax-code:dom-event` checks `name.startsWith("openchamber:")` (preload.js:15) and outbound `event.listen` checks the same prefix (66); (3) the `dom-event` dispatch is wrapped in `try/catch` (preload.js:16-20) because `window`/`CustomEvent` may not be ready at preload time — the catch is a documented best-effort suppression ("window may not be ready yet; the event is best-effort", 19), not a silent error; (4) `event.listen` returns a `Promise<unlisten>` (71) matching the Tauri contract (`Promise<() => void>`), and the unlisten correctly calls `ipcRenderer.removeListener(channel, wrapped)` (71) preventing listener leaks; (5) the `recordStartupEvent` defaults `details` to `{}` (36) so an undefined argument cannot reach the main handler. The `{ once: true }` option (28) is the correct idempotency guard for the app-ready signal. The boot-outcome is exposed as a value (not a function) at load time (42), consistent with the comment that Electron only loads the renderer after the page is reachable. Error translation: IPC rejection surfaces as a rejected Promise to the renderer caller (52), which the UI layer handles.

## Step 4 — Performance

The preload runs once at renderer load and sets up a small fixed set of bridge bindings — there is no hot path, no loop, no allocation pressure. The three `contextBridge.exposeInMainWorld` calls (preload.js:33, 42, 48) are one-time registrations. The `ipcRenderer.on("ax-code:dom-event", ...)` listener (13) persists for the renderer lifetime and fires per main-process event — each fire does a string `startsWith` check (15) and, if matched, a `window.dispatchEvent(new CustomEvent(...))` (17), both O(1). The `event.listen` channel subscriptions (65-72) are bounded by the number of openchamber: channels the UI subscribes to (a handful), each adding one `ipcRenderer.on` listener with a matching `removeListener` unlisten returned to the caller — no unbounded growth provided the UI calls unlisten on teardown (that is the UI layer's responsibility, covered by the UI lifecycle scans). No synchronous IO, no caching, no timers. No performance finding.

## Step 5 — Design

The design is the correct Electron preload pattern: minimal, `contextBridge`-based (not `window.X = ...` direct assignment), capability-scoped, and fail-closed. Exposing a Tauri-compatible `__TAURI__` shim (preload.js:48-74) so the shared `@openchamber/ui` package works in both shells without per-shell code is a sound reuse decision — the comment at 44-47 documents the rationale. The `openchamber:` namespace scoping is applied consistently to both the inbound dom-event bridge (15) and the outbound event.listen (66), which is the right consistency — a single namespace constant would be marginally cleaner but the literal prefix is used only twice. Cohesion is high for a 74-line file: it has one job (bridge main↔renderer with scoping) and does nothing else. Boundary conformance is clean: it imports only `electron` (`contextBridge`, `ipcRenderer`), `./desktop-boot-outcome`, and `./preload-ipc-policy` — no cross-package or core-runtime leakage. The file is plain CommonJS (`require`, preload.js:3-5) which is required for Electron preload scripts (they cannot be ESM without `sandbox: false` + bundler config), so this is intentional, not a style defect.
