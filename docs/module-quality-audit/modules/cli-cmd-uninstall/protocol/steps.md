## Step 4 Destructive-operation safety and error handling

The package-manager command is the constant argv array `["brew", "uninstall", "ax-code"]` at `packages/ax-code/src/cli/cmd/uninstall.ts:179-186`; `Process.run` passes argv to `cross-spawn` without enabling a shell by default (`packages/ax-code/src/util/process.ts:108-119`, `:193-223`), so no command text comes from a profile or path. Recursive removal is forceful but remains confined to the precomputed targets (`uninstall.ts:151-164`). A Medium correctness risk remains for symlinked shell profiles: `cleanShellConfig` reads the candidate path and calls `Filesystem.write` (`uninstall.ts:261-299`), while that helper writes a sibling temporary file and renames it over the path (`packages/ax-code/src/util/filesystem.ts:83-115`). Renaming over a symlink replaces the link rather than editing its referent, which can detach a dotfile-managed profile and leave the original target unchanged. The routine should resolve and deliberately preserve symlink semantics before rewriting.

## Step 5 Shell-profile matching and data preservation

The installer writes a two-line marker plus PATH command at `install:674-683`, using `fish_add_path` or `export PATH` at `install:800-815`. Cleanup recognizes that exact marker and direct ax-code PATH forms at `packages/ax-code/src/cli/cmd/uninstall.ts:268-290`, then normalizes trailing blank lines and writes one final newline (`uninstall.ts:293-299`). Discovery covers common fish, zsh, bash, ash, and sh locations (`uninstall.ts:219-258`), but it does not honor arbitrary `ZDOTDIR` values even though installation does at `install:775-776`; the `sh` candidate list also omits `.ashrc`, which the installer considers first at `install:784-785`. These are Low residual-uninstall gaps: custom layouts can retain the PATH entry. The marker-following rule at `uninstall.ts:276-280` also removes any adjacent `fish_add_path` line, so tighter matching would better protect user-edited profiles.

## Step 6 Performance and scalability

Before confirmation, each existing target is measured (`packages/ax-code/src/cli/cmd/uninstall.ts:105-123`). `getDirectorySize` walks directories recursively and serially, then performs an extra `stat` for every regular file (`uninstall.ts:301-321`). This is linear in the number of entries and can make the summary slow for large caches or session histories; read/stat failures are intentionally treated as zero contribution, so the displayed size is advisory. Deletion itself delegates to native recursive `fs.rm` (`uninstall.ts:157-164`). There is no long-lived hot-path cost because uninstall is a one-shot command, but an iterative traversal or bounded parallel stats would avoid deep recursion and reduce latency. `formatSize` promotes at the one-decimal binary-unit boundary (`uninstall.ts:324-332`), preventing misleading `1024.0 KB` and `1024.0 MB` labels.
