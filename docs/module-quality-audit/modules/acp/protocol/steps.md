## Step 1 Scope and ownership map

The public protocol implementation is concentrated in `packages/ax-code/src/acp/agent.ts`: `ACP.init` constructs one connection-bound `ACP.Agent` (`agent.ts:92-125`), and the class implements initialization, authentication, session lifecycle, prompt, cancel, model, and mode RPCs (`agent.ts:251-342`, `344-425`, `677-758`). State ownership is split cleanly: `ACPSessionManager` owns the ACP-to-internal-session mapping (`session.ts:8-23`), `session-mode.ts:63-212` assembles models, modes, commands, and MCP connections, `prompt.ts:10-113` translates content and usage, `usage.ts:27-73` publishes context usage, and `agent-adapter.ts:18-275` contains model/tool/URI adapters. `types.ts:5-24` is the narrow shared state/config contract; `utils.ts:9-120` owns validated cursors, data-URL decoding, and todo conversion. The CLI boundary creates the local HTTP SDK and ACP stdio connection at `packages/ax-code/src/cli/cmd/acp.ts:19-84`.

## Step 2 Trust boundaries and failure model

An ACP host supplies working directories, prompt resources, MCP definitions, permission choices, and session/model identifiers. The highest-risk path is secret handling: session creation stores the caller's complete `McpServer[]` in state (`session.ts:76-82`) and logs that state at INFO (`session.ts:83`); load repeats the same behavior (`session.ts:110-117`). Those MCP records can contain remote header values or local environment values, as shown by their direct conversion at `session-mode.ts:129-154`. The shared logger serializes object fields without redaction (`packages/ax-code/src/util/log.ts:343-354`, `383-418`), so API keys passed in MCP headers or environment variables can land in text and JSON logs. I classify this as HIGH confidentiality exposure, not Critical, because the sink is local runtime logging and exploitation requires a local ACP client or later access to the user's logs. The permission/edit boundary also accepts a filepath and diff from an internal permission event (`agent.ts:524-533`), but it writes only after the ACP client selects a non-reject option.

## Step 3 Public-path correctness

New/load/fork/resume all resolve a model, track the internal session, populate mode/model metadata, and translate provider authentication failures to `authRequired` (`agent.ts:280-342`, `370-425`). Two concrete correctness defects remain. First, an approved edit that intentionally empties a file produces `""` from `getNewContent`, but `if (newContent)` suppresses the client write (`agent.ts:529-537`); the check must distinguish `undefined` from the valid empty string. Second, every leading-slash prompt enters command routing (`agent.ts:714-717`), but when the name is absent from `command.list` and is not `compact`, the switch does nothing and returns `end_turn` (`agent.ts:729-749`). That silently discards an unknown slash-prefixed user message instead of reporting an invalid command or submitting it as ordinary text. Model changes have a similar validation gap: `parseModelSelection` can return an unknown provider/model unchanged (`agent-adapter.ts:247-275`), and `unstable_setSessionModel` stores it without checking the advertised model list (`agent.ts:677-691`).

## Step 4 Concurrency, lifecycle, and resource bounds

The agent subscribes once per connection (`agent.ts:128-135`), isolates events by session (`agent.ts:164-248`), bounds replay queues at 500 events per session (`agent.ts:110-111`, `166-177`), and cancels the subscription, timers, caches, replay state, and session map on connection abort (`agent.ts:119-125`, `152-162`). Permission requests are serialized per session with a keyed write lock (`agent.ts:496-504`), so a blocked prompt in one session does not serialize unrelated sessions. The reconnect loop needs hardening: a cleanly-ended event stream immediately reiterates without delay (`agent.ts:137-149`), which can spin and repeatedly call `sdk.global.event`; conversely, a thrown subscription error escapes the loop and the one outer catch only logs it (`agent.ts:131-134`), leaving updates permanently stopped. A bounded backoff/retry policy should cover both clean EOF and transient errors. `ACPSessionManager` caps retained state at 1024 (`session.ts:11-39`), but reads and mutations do not refresh insertion order (`session.ts:56-58`, `132-160`), so the stated LRU behavior is actually creation/load-order eviction.

## Step 5 Cohesion and cross-session isolation

The adapter/session/prompt split keeps wire translation separate from protocol orchestration, and `ACPSessionState` contains only the internal id, cwd, MCP list, model, variant, and mode (`types.ts:5-16`). Model variants are consistently advertised and round-tripped through `buildAvailableModels`, `formatModelIdWithVariant`, and `buildVariantMeta` (`agent-adapter.ts:197-245`). One ownership mismatch is MCP lifetime: the protocol records MCP servers per ACP session (`session.ts:76-82`, `110-116`), yet `loadSessionMode` installs each by name through the directory-scoped SDK MCP registry (`session-mode.ts:158-173`). The underlying route calls process/project MCP state (`packages/ax-code/src/server/routes/mcp.ts:65-93` and `packages/ax-code/src/mcp/impl.ts:487-527`), so two ACP sessions in the same directory can replace a same-named server or inherit a server created for another session. Session teardown only clears the local map (`agent.ts:152-161`) and does not remove those dynamic MCP clients. Either the contract should explicitly make MCP definitions connection/directory scoped or the implementation should own per-session namespacing and cleanup.

## Step 6 Error handling and code health

Fallbacks around default-model discovery are observable through structured error logs (`agent-adapter.ts:75-93`) and strict SDK calls reject empty session/provider/command payloads (`session.ts:61-71`, `95-106`; `session-mode.ts:87-115`). In contrast, every MCP add failure is caught and reduced to a log entry (`session-mode.ts:158-171`), after which `session/new` or `session/load` still reports success; clients cannot tell that requested tools are unavailable. Most outbound `sessionUpdate` failures are deliberately best-effort (`agent.ts:230-245`, `443-490`, `559-640`), which protects prompt completion but warrants a connection-health metric because repeated failures otherwise become log-only degradation. The eight candidate files contain no TODO/FIXME markers. The remaining unsafe edges are localized: ACP content parsing uses non-null assertions for SDK-required text, MIME, and URI fields (`prompt.ts:31`, `45`, `52`, `58`), while externally reusable decoders validate malformed JSON, base64, and numeric cursors (`utils.ts:34-54`, `56-115`).

## Step 7 Test evidence and missing regressions

The targeted ACP suite passed: 8 files and 33 tests. Existing coverage checks case-insensitive file/zed URI handling (`test/acp/agent-adapter.test.ts:7-38`), remote image prompt conversion (`test/acp/agent-prompt.test.ts:90-122`), interface method presence (`test/acp/agent-interface.test.ts:21-49`), cursor rejection and data-URL decoding (`test/acp/todo-plan-entries.test.ts:39-117`), malformed session timestamps (`test/acp/session-list.test.ts:42-75`), and event isolation, disposal, permission serialization, tool streaming, and replay deduplication (`test/acp/event-subscription.test.ts:263-388`, `429-577`, `579-715`, `767-888`). Missing regressions align with the issues above: no test covers an edit diff whose result is an empty string, an unknown slash command, invalid model selection, MCP credentials absent from INFO logs, same-name MCP isolation across two sessions, or event-stream EOF/error recovery. `session-mode.ts`, `session.ts`, and `usage.ts` also lack direct unit tests despite owning important state and capability behavior.

## Step 8 Compatibility and protocol contract

Backward-compatible helper exports are deliberately available both at module scope and on the `ACP` namespace (`agent.ts:74-90`). Initialization advertises load, fork/list/resume, HTTP/SSE MCP, embedded context, and images (`agent.ts:251-273`), while the class implements every SDK-routed method named in `agent-interface.test.ts:25-47`. Authentication is a contract caveat: `initialize` always advertises `ax-code-login` (`agent.ts:253-272`) but `authenticate` always returns method-not-found (`agent.ts:276-278`); clients without support for the custom `terminal-auth` metadata can reasonably invoke the advertised method and fail. Documentation has drifted too: `packages/ax-code/src/acp/README.md:114-123` still says session modes and persistence/load history are unimplemented, although mode selection is implemented at `session-mode.ts:20-60` and load replays stored messages at `agent.ts:299-335`. Compatibility work should preserve existing helper names and variant metadata while making authentication and documentation match actual behavior.

## Step 9 Findings, severity, and exit decision

No file exists under `docs/module-quality-audit/modules/acp/findings/`, so there is no pre-existing Critical item requiring `reverify.md`. This review records one HIGH issue (MCP header/environment secrets serialized at INFO in `session.ts:83,117`), and MEDIUM issues for empty-file optimistic edits (`agent.ts:529-537`), silent unknown slash commands (`agent.ts:717-749`), invalid model acceptance (`agent.ts:677-691`), event subscription EOF/error behavior (`agent.ts:128-149`), and directory-scoped MCP state masquerading as session-scoped state (`session-mode.ts:158-173`). The fail-soft MCP-add behavior is LOW-to-MEDIUM depending on whether the missing server is required. Recommended order is to redact/remove session-state logging first, then add focused regressions for empty edits and unknown commands, then define event retry and MCP ownership semantics.
