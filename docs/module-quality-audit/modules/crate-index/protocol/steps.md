## Step 2 Inputs and trust boundaries

Three caller-controlled paths cross into native IO: the database path is opened at `crates/ax-code-index/src/store.rs:25-35`, file hashing opens and streams the supplied path at `crates/ax-code-index/src/hasher.rs:14-26`, and lock construction creates the supplied parent directory at `crates/ax-code-index/src/lock.rs:23-30`. Database values use bound SQLite parameters, including optional edge filters at `crates/ax-code-index/src/edge.rs:98-109`. Bulk node, edge, and ingest payloads reject malformed JSON (`crates/ax-code-index/src/node.rs:62-64`, `crates/ax-code-index/src/edge.rs:56-58`, `crates/ax-code-index/src/file.rs:203-208`), but the two find methods silently replace malformed option JSON with unfiltered defaults at `crates/ax-code-index/src/node.rs:123-127` and `crates/ax-code-index/src/node.rs:168-172`; that inconsistency is a low-severity API-hardening gap.

## Step 3 Relational correctness and atomicity

Multi-table destructive operations are transactionally grouped: project clearing deletes edges, nodes, files, and the cursor before commit (`crates/ax-code-index/src/cursor.rs:61-81`); orphan pruning removes touching edges before nodes and file rows (`crates/ax-code-index/src/file.rs:157-189`); and per-file ingest performs replacement plus metadata upsert in one transaction (`crates/ax-code-index/src/file.rs:210-276`). The schema supplies project/name/file and edge endpoint indexes (`crates/ax-code-index/src/schema.rs:21-25`, `crates/ax-code-index/src/schema.rs:42-46`). A MEDIUM integrity risk remains in pruning: `scope_prefix` becomes the raw textual pattern `escaped + "%"` at `crates/ax-code-index/src/file.rs:130-145`, so `/repo/worktree` also selects `/repo/worktree-old`. The production caller passes `Instance.directory` without a trailing separator (`packages/ax-code/src/cli/cmd/index-graph.ts:575-585`), and the existing sibling test compares `proj1` with `proj2`, not the colliding `proj10` case (`packages/ax-code/test/code-intelligence/query.test.ts:609-634`). This can remove regenerable index rows outside the intended walk root.

## Step 4 Concurrency, liveness, and lifecycle

`IndexStore` serializes a single SQLite connection behind `Mutex<Option<Connection>>` and converts poisoned-lock recovery and post-close access into controlled behavior (`crates/ax-code-index/src/store.rs:12-20`, `crates/ax-code-index/src/store.rs:76-105`). Advisory locks retain the locked descriptor until explicit release or `Drop` (`crates/ax-code-index/src/lock.rs:45-63`, `crates/ax-code-index/src/lock.rs:166-189`). A MEDIUM liveness defect exists in native ID generation: `ascending` samples `now_ms()` once (`crates/ax-code-index/src/id.rs:88-94`), while `reserve_timestamp_counter` loops with that fixed `current` and merely yields after counter 255 (`crates/ax-code-index/src/id.rs:69-85`). On a single synchronous N-API thread, a 257th reservation in the same millisecond cannot observe a later clock and can spin indefinitely unless another thread advances the atomic state. The test at `crates/ax-code-index/src/id.rs:162-169` proves a separately supplied later timestamp works but does not exercise the looping function at saturation.

## Step 5 Cost and scalability

Writes are sensibly batched in transactions (`crates/ax-code-index/src/node.rs:70-97`, `crates/ax-code-index/src/edge.rs:64-88`), hashing uses an 8 KiB streaming buffer (`crates/ax-code-index/src/hasher.rs:14-24`), and the schema indexes the principal project-scoped lookups (`crates/ax-code-index/src/schema.rs:21-25`, `crates/ax-code-index/src/schema.rs:42-46`). The interval structure, however, is not O(log n) as documented at `crates/ax-code-index/src/interval_tree.rs:41-45`: after `partition_point`, both lookup variants scan every preceding interval (`crates/ax-code-index/src/interval_tree.rs:108-130`, `crates/ax-code-index/src/interval_tree.rs:151-164`). Worst-case lookup is O(n), and initial sorting is O(n log n), so the “native fast-path” claim at `packages/ax-code/src/code-intelligence/builder-impl.ts:255-258` overstates the acceleration. This is a MEDIUM performance/contract finding for large symbol sets.

## Step 6 Design and representation boundaries

The module split is cohesive: row decoding and graph operations live with nodes, edges, files, and cursors, while connection ownership stays in `crates/ax-code-index/src/store.rs:17-20` and schema text stays in `crates/ax-code-index/src/schema.rs:1-81`. The TypeScript adapter centralizes native availability and JSON decoding (`packages/ax-code/src/code-intelligence/native-store.ts:34-50`, `packages/ax-code/src/code-intelligence/native-store.ts:80-91`), matching the generated NAPI declarations at `packages/ax-code-index-core/index.d.ts:25-69`. Two representation seams deserve follow-up: `ingest_file` accepts authoritative `project_id`/`file_path` arguments but does not validate that embedded node, edge, and file metadata fields match them before inserting (`crates/ax-code-index/src/file.rs:195-208`, `crates/ax-code-index/src/file.rs:243-273`), and interval “size” assumes 10,000 character units per line (`crates/ax-code-index/src/interval_tree.rs:14-20`), which is heuristic rather than a true containment ordering.
