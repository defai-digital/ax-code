## Step 2 Threat and failure model

The main trust boundaries are child-process environments, archive paths, filesystem paths, and HTTP directory headers. `Env.sanitize` removes injection variables, helper sockets, secret-like names, credential URL names, and URL userinfo at `packages/ax-code/src/util/env.ts:64-83`; provider keys are restored only for a named CLI provider at `packages/ax-code/src/util/env.ts:52-62`. ## Step 3 Correctness and edge cases

Atomic file replacement is well structured: `Filesystem.write` writes a sibling temporary file, preserves an existing mode, renames, and removes the temporary on failure (`packages/ax-code/src/util/filesystem.ts:83-116`); `writeStream` likewise keeps the old destination intact until its pipeline succeeds (`packages/ax-code/src/util/filesystem.ts:122-143`). Invalid URI/base64 input returns a stable empty string (`packages/ax-code/src/util/data-url.ts:1-16`), and unknown thrown values have a guarded string-conversion fallback (`packages/ax-code/src/util/error-message.ts:1-12`). Two low edge cases remain: `truncate("abcd", 2)` returns `"..."`, contradicting its at-most-`max` contract because the suffix is never shortened (`packages/ax-code/src/util/format.ts:1-7`), and `Context.use` tests `if (!result)` even though generic `T` permits valid falsy values (`packages/ax-code/src/util/context.ts:10-24`). Current context users are object-shaped, so the latter is latent rather than an observed production failure.

## Step 4 Concurrency and lifecycle safety

The semaphore transfers an occupied permit directly to the next FIFO waiter and releases in `finally`, avoiding the open-slot race (`packages/ax-code/src/util/concurrency.ts:29-64`). `FanOut.run` bounds workers, gives each member its own abort controller/timer, and removes the parent listener in `finally` (`packages/ax-code/src/util/fan-out.ts:33-75`). A Medium concurrency observation exists in stale lock stealing: `maybeSteal` reads ownership at `packages/ax-code/src/util/filelock.ts:64-70` and later unlinks at `:71-80` without verifying that the lock body is still the one read. If the old owner releases and another process acquires between those operations, the stealer can delete the new owner’s lock and then win `open(..., "wx")` at `filelock.ts:34-41`, allowing overlapping critical sections. Disposal does recheck PID/host at `filelock.ts:147-159`, but that does not close the acquisition race; a per-acquisition token plus compare-before-delete/rename is recommended.

## Step 5 Performance and resource bounds

Bulk work has explicit ceilings: `mapWithConcurrency` creates at most `min(limit, items.length)` workers and preserves output order (`packages/ax-code/src/util/concurrency.ts:73-90`), while the global caps are 50 file operations and 20 network operations (`concurrency.ts:93-99`). Git lock contention is retried at most five times with linear 50 ms increments (`packages/ax-code/src/util/git.ts:48-56`), so retry delay is bounded. Upward file discovery terminates at the requested stop or filesystem root (`packages/ax-code/src/util/filesystem.ts:225-270`); `globUp` can rescan once per ancestor but has no infinite path. Environment sanitation and Git-output parsing are single-pass over entries or lines (`packages/ax-code/src/util/env.ts:64-81`, `packages/ax-code/src/util/git-output.ts:58-78`). No unbounded in-memory queue or hot-loop regression was found in this slice.

## Step 6 Design and ownership

Responsibilities are narrow and dependencies point toward shared infrastructure: archive extraction delegates execution to `Process.run` (`packages/ax-code/src/util/archive.ts:1-20`), globbing wraps `fast-glob`/`minimatch` without embedding caller policy (`packages/ax-code/src/util/glob.ts:1-44`), and Git execution converts `Process.run` results into a small stable `GitResult` (`packages/ax-code/src/util/git.ts:4-46`). `fn` centralizes Zod parsing and deliberately exposes `force` as a validation bypass for trusted internal values (`packages/ax-code/src/util/fn.ts:3-17`). `defer` supplies both disposal protocols at runtime while its conditional type advertises the appropriate one (`packages/ax-code/src/util/defer.ts:1-11`). The layering is coherent for a shared utility module; the lock identity weakness belongs in `filelock`/`process-lock`, not in its storage consumers.

## Step 7 Dead code, error handling, and maintainability

Cleanup failures for temporary files are intentionally secondary to the original write/pipeline error at `packages/ax-code/src/util/filesystem.ts:101-114` and `:140-142`; unlike an empty catch on primary work, these sites preserve the actionable exception. `normalizePath` also has a documented best-effort fallback on Windows (`filesystem.ts:150-161`). The catch/rethrow in `fn` adds no behavior (`packages/ax-code/src/util/fn.ts:5-11`) and can be simplified. Repository use search found `Filesystem.writeStream` exercised by tests at `packages/ax-code/test/util/filesystem.test.ts:448-590` but no production caller, so its 22-line surface is currently dormant.
