## Step 1 Map

The unit `desktop-web-git` lives under `desktop/packages/web/server/lib/git/` and is organized as a barrel plus three concern areas. `desktop/packages/web/server/lib/git/index.js:4-6` re-exports `./service.js`, `./credentials.js`, and `./identity-storage.js`. `desktop/packages/web/server/lib/git/routes.js:1-1098` is a single `registerGitRoutes(app)` Express registrar exposing ~50 `/api/git/*` endpoints; it lazily imports the barrel through a memoized `getGitLibraries()` closure (`routes.js:2-8`). `desktop/packages/web/server/lib/git/credentials.js:5` reads `~/.git-credentials` and exposes `discoverGitCredentials` (`credentials.js:20-49`, host/username only) and `getCredentialForHost` (`credentials.js:51-77`, returns the token). `desktop/packages/web/server/lib/git/identity-storage.js:6-7` persists profiles to `~/.config/openchamber/git-identities.json`. `desktop/packages/web/server/lib/git/service.js` (4169 lines) is the core engine: git binary resolution, path-traversal guards, identity config, status/diff, and a substantial worktree subsystem.

## Step 2 Trust and failure boundaries

This module brokers between untrusted HTTP parameters and the local filesystem plus a spawned `git` process, so the boundaries are: filesystem reads of credential/identity stores, child-process execution of git, request-controlled `directory`/`path`/`hash`/`branch` inputs, and path containment. Credential token material is gated well: only `discoverGitCredentials` (no token field) is wired to a route at `desktop/packages/web/server/lib/git/routes.js:74-83`, while `getCredentialForHost` (`credentials.js:51-77`) is exported from the barrel but never bound to an HTTP surface. Identity files are written with restrictive permissions — `desktop/packages/web/server/lib/git/identity-storage.js:10` creates the directory `0o700` and `identity-storage.js:23,29` writes the JSON `0o600` via a pid+random temp file then atomic rename (`identity-storage.js:16-37`). SSH key paths flow into `core.sshCommand`; `desktop/packages/web/server/lib/git/service.js:194-228` rejects shell metacharacters `` `$!"';&|<>(){}[]*?#~ `` before quoting. A genuine residual surface is `runWorktreeStartCommand` (`service.js:1076-1112`), which intentionally executes user/project start scripts through `bash -lc` / `cmd /c`; that is by-design scripting, not an injection vector, but it is the highest-privilege action reachable from worktree creation.

## Step 3 Correctness

Path containment is enforced at every file-touching entry point. `validateRepositoryFilePaths` (`desktop/packages/web/server/lib/git/service.js:387-397`) and `resolveRepositoryFilePath` (`service.js:406-412`) reject `..` and absolute escapes, and `stageFiles`/`unstageFiles` re-validate after resolving repo-relative paths (`service.js:2456-2504`, `2510-2538`). Commit-hash surfaces (`checkoutCommit`, `cherryPick`, `revertCommit`, `resetToCommit`) all gate on `isValidCommitHash` (`service.js:660-662`, regex `/^[0-9a-fA-F]{7,40}$/`) before passing to git, and the route layer repeats that guard (`routes.js:778, 797, 816, 835`), so option injection via a forged hash is blocked at two layers. Destructive operations are guarded: `resetToCommit` hard mode requires a clean tree unless `force` (`service.js:2814-2820`), `removeWorktree` refuses to delete the primary workspace (`service.js:3249-3251`), and `removeRemote` rejects removing `origin` (`service.js:3850-3852`). Index mutations are serialized per-repo through `withGitIndexMutationQueue` (`service.js:351-378`), keyed by resolved repo root, which prevents interleaved `git add`/`commit` races during rapid UI toggling. `rebase`/`merge` reject refs beginning with `-` (`service.js:3875-3877`, `3929-3931`) to stop option smuggling via a positional argument.

## Step 4 Performance

`getStatus` offers a `light` mode (`desktop/packages/web/server/lib/git/service.js:1486`, `1495-1500`) that skips numstat and new-file line counting for cheap polling, and the heavy path bounds work: new-file stat estimation caps candidates at 200 files (`service.js:1536-1537`) and processes them in concurrency batches of 12 (`service.js:1545`, `1619-1625`) instead of the prior sequential await-per-file loop. A 30-second TTL `remoteExistenceCache` (`service.js:19`, `757-781`) avoids repeated `git remote get-url` probes during `getStatus`, and `countStashFiles` uses a 4-worker pool (`service.js:2219-2238`). The clearest remaining hotspot is `filterActiveRemoteBranches` (`service.js:2681-2716`): `getBranches` fans out `git ls-remote --heads` to **every** configured remote inside an uncapped `Promise.all`, so a repo with several remotes pays a network round-trip to each on every branch-list call, with no cache. That is a latency risk for multi-remote repos but not a correctness defect. The `/api/git/worktrees` route deliberately swallows errors and returns `[]` with an `X-OpenChamber-Warning` header (`routes.js:860-865`) to suppress client retry storms.

## Step 5 Design

The barrel keeps the public surface tidy, and the lazy `getGitLibraries()` memoization in `desktop/packages/web/server/lib/git/routes.js:2-8` is a reasonable cold-start optimization. Two seams are weak. First, `routes.js` is a 1098-line single function with the `directory`-required check duplicated ~40 times (e.g. `routes.js:88-91`, `206-209`, `314-317`); a `requireDirectory(req, res)` helper would remove that repetition and the chance of one handler forgetting it. Second, business logic has leaked into the route layer: `/api/git/set-identity` at `routes.js:165-176` synthesizes a profile from the global identity and parses the ssh command with a brittle `globalIdentity.sshCommand.replace("ssh -i ", "")` (`routes.js:175`); that derivation belongs in `service.js` next to `buildSshCommand` (`service.js:233-236`) so the producer and consumer of the string agree. Within `service.js`, the worktree subsystem (`service.js:564-1369` — name generation, project metadata, bootstrap queue, sandbox sync) is effectively a self-contained module and would be easier to reason about split into `worktree.js`, but the current coupling to shared helpers (`normalizeDirectoryPath`, `runGitCommandOrThrow`) makes that a moderate refactor rather than a quick move.

## Step 6 Hygiene and dead code

The four empty catch sites flagged for this unit are all in `desktop/packages/web/server/lib/git/identity-storage.js`: line 13 (`chmodSync` after `mkdirSync`), line 26 (`chmodSync` on the temp file), line 30 (`chmodSync` after rename), and line 34 (`rmSync` of the temp file on failure). These are defensive best-effort permission hardening — `chmod` can legitimately fail on filesystems without POSIX perms (Windows, exFAT) and on the failure path the `rmSync({force:true})` already tolerates a missing file — so swallowing is defensible, but each site lacks an explanatory comment and should grow one. No TODO/FIXME markers appear anywhere in the unit. The single-path wrappers `stageFile`/`unstageFile` (`service.js:2452-2454`, `2506-2508`) are thin delegators kept for API symmetry. `collectDiffs` (`service.js:2147-2160`) is exported but not invoked within this directory; it is a public helper rather than dead code.

## Step 7 Tests

`desktop/packages/web/server/lib/git/credentials.test.js` (3 cases) covers host/pathname dedup, host lookup returning the token, missing-file-as-empty, and explicitly asserts no preflight `existsSync` (`credentials.test.js:43-48`, `63-68`). `identity-storage.test.js` (4 cases) verifies the `0o700`/`0o600` permission bits (`identity-storage.test.js:45-46`, skipped on win32), temp-file cleanup on write failure (`:49-55`), and the same no-preflight invariant. `routes.test.js` (7 cases) exercises only the stage/unstage endpoints through the `createRouteRegistry`/`createMockResponse` harness (`desktop/packages/web/server/test-helpers/route-harness.js:1-91`), covering legacy single-path, bulk `paths`, invalid-entry filtering, and empty-payload rejection — but the remaining ~45 endpoints have no direct route-level tests. `service.test.js` (the largest, 502 lines) is strong on safety and mutations: Windows path validation via injected `path.win32` (`service.test.js:126-135`), soft/mixed/hard/force reset semantics (`:307-417`), cherry-pick/revert conflict reporting, stash ref dedup, and hash-format rejection for all four hash-gated operations. The main gaps are the complex push upstream-fallback state machine (`service.js:2282-2409`), `pull`, `merge`/`rebase` conflict paths, and the entire worktree create/remove/validate lifecycle — none have integration tests here.

## Step 8 Findings

`docs/module-quality-audit/modules/desktop-web-git/findings/AUDIT-desktop-web-git-empty-catch.md` registers a single Low-severity, deferred item: the four `chmod`/`rm` empty catches in `identity-storage.js`. This independent pass re-read each site and confirms the dispositions are accurate — they are best-effort permission hardening where swallowing is acceptable, and adding local comments (not code changes) is the right closure. No new Critical or High issue was accepted: the `filterActiveRemoteBranches` multi-remote fan-out is a performance note, the route-layer sshCommand parsing is a fragility/design note, and neither demonstrates an invariant break. The credential token never reaches an HTTP response, and the path/hash/branch guards hold, so there is no security finding to escalate.
