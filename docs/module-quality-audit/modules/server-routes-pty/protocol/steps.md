# Nine-step review: server-routes-pty

## Step 1 Scope and public surface

The reviewed unit is `server-routes-pty`. `packages/ax-code/src/server/routes/pty.ts:15-22` exports the reconnect-cursor parser, while `:24-239` exports a lazy Hono router with list, create, get, update, remove, and WebSocket-connect operations. The router is mounted at `/pty` by `packages/ax-code/src/server/server.ts:299-301`, so these handlers form a public local HTTP boundary rather than an internal helper API. Parameter identity is centralized through `PTY_ID_PARAM` and `withPtyID` at `packages/ax-code/src/server/routes/route-params.ts:28-30,44-61`.

## Step 2 Trust boundary and input controls

The highest-impact input is `POST /pty`: `packages/ax-code/src/server/routes/pty.ts:47-69` validates `Pty.CreateInput` before delegating, and that schema permits command, arguments, cwd, title, and environment at `packages/ax-code/src/pty/index.ts:237-243`. Network exposure is constrained by the local-only bind assertion at `packages/ax-code/src/server/server.ts:345-366` and `packages/ax-code/src/runtime/listen-security.ts:27-31`; browser mutations and upgrades also face the origin check at `server.ts:183-195`, with optional runtime-token or Basic authentication at `:166-182`. ## Step 3 REST control-flow correctness

List and create are direct, schema-validated delegations (`packages/ax-code/src/server/routes/pty.ts:26-69`). GET correctly turns an absent session into `NotFoundError` at `:89-96`, which the global envelope maps to 404 through `packages/ax-code/src/server/error.ts:46-64,86-88`. A real contract defect remains for the other ID operations: PUT returns `c.json(info)` at `pty.ts:116-121`, but `Pty.update` returns `undefined` for an absent ID at `packages/ax-code/src/pty/index.ts:506-517`, producing HTTP 200 with an empty body instead of the declared `Pty.Info`. DELETE always returns JSON `true` at `pty.ts:141-145`, although `Pty.remove` silently returns for an absent ID at `pty/index.ts:520-532` and the route advertises 404 at `pty.ts:138`. This review classifies the combined missing-resource false-success as Medium API correctness work: check existence or make the domain methods report absence, then add route-level 404 tests.

## Step 4 WebSocket and reconnect lifecycle

The connect route validates the branded ID, parses only `-1` or decimal safe integers, and checks session existence before constructing its socket lifecycle (`packages/ax-code/src/server/routes/pty.ts:165-170`; parser at `:15-22`). `onOpen` rejects malformed raw sockets (`:172-199`), awaits `Pty.connect`, handles a close that races the await, and flushes queued input only after readiness (`:200-213`). `onClose` and `onError` share an idempotent `closed` guard at `:226-235`, so the subscriber cleanup callback is not invoked twice. The domain connect path registers a connection-identity key, replays retained output, closes on failed sends, and returns the cleanup callbacks at `packages/ax-code/src/pty/index.ts:333-376`. If the PTY disappears between the route's precheck and `Pty.connect`, the domain closes the socket at `:335-339`; the route's optional callback calls keep that race from throwing.

## Step 5 Resource and performance behavior

Pre-ready client input is capped at 100 messages and drops the oldest entry when full (`packages/ax-code/src/server/routes/pty.ts:186-221`), preventing an unresolved connection from growing that queue without bound. Retained terminal output is independently capped at 2 MiB (`packages/ax-code/src/pty/index.ts:22-23,485-489`) and replay is sent in 64 KiB chunks (`:120-128,353-365`). Subscriber entries are removed when socket state is not open, identity is recycled, or send throws (`:464-482`), and PTY teardown disposes callbacks, kills the process, closes sockets, and clears the map at `:269-303`. A lower-severity operational risk remains: `Pty.create` inserts every process into the per-instance session map at `:450-459` with no concurrent-session ceiling; HTTP rate limiting permits 120 mutating calls per minute per resolved route key at `packages/ax-code/src/server/middleware.ts:55-81`, but it is not a lifetime process quota.

## Step 6 Ownership and protocol contracts

The separation is generally coherent: the route owns HTTP/OpenAPI validation and WebSocket event adaptation, while `packages/ax-code/src/pty/index.ts:83-109,306-377,400-532` owns replay math, process state, subscription state, and lifecycle events. Cross-runtime upgrade selection stays in `packages/ax-code/src/server/runtime-adapter.ts:57-83`, avoiding Bun/Node branching in the route. One Low documentation issue is that `packages/ax-code/src/server/routes/pty.ts:148-163` describes connect as a 200 JSON boolean response even though the implementation upgrades to a WebSocket and emits text plus a binary metadata control frame (`packages/ax-code/src/pty/index.ts:73-81,353-365`). The generated API description therefore cannot communicate the actual handshake or framing contract to clients.

## Step 7 Failure handling and maintainability

There are no empty catch blocks or TODO markers in the candidate route. Connection setup failures are logged with the PTY ID, pending data is cleared, and the WebSocket is closed at `packages/ax-code/src/server/routes/pty.ts:209-213`; invalid raw-socket shapes also fail closed at `:178-199`. No dead route or unused export was found.
