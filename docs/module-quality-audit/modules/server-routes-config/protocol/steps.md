# Nine-step review: server-routes-config

## Step 1 Establish Scope and Public Surface

The `server-routes-config` unit owns the redaction helpers and three lazy Hono handlers exported from `packages/ax-code/src/server/routes/config.ts:14-134`: `GET /config`, `PATCH /config`, and `GET /config/providers` are defined at lines 136-212. The application mounts them after project-directory validation and `Instance.provide` at `packages/ax-code/src/server/server.ts:258-301`. The same helpers are reused by the global config routes at `packages/ax-code/src/server/routes/global.ts:381-424` and the provider discovery route at `packages/ax-code/src/server/routes/provider.ts:225-237`, so their effective public surface is wider than this router alone.

## Step 2 Inspect Trust and Secret Boundaries

Server-wide runtime-token/basic authentication, origin checks, rate limiting, and CORS precede the route at `packages/ax-code/src/server/server.ts:155-207`. Within the unit, `redactConfig` masks nonempty MCP headers/environment values and MCP OAuth `clientSecret` at `packages/ax-code/src/server/routes/config.ts:77-116`; provider option names matching `key|secret|token|password|credential|auth` are masked at lines 16 and 30-37. `redactProviderInfo` also removes the top-level provider key at lines 125-131. These are important local defenses because `Provider.Info` explicitly permits a credential-bearing `key` and arbitrary options at `packages/ax-code/src/provider/model-info.ts:64-72`.

## Step 3 Trace Read and Update Correctness

`GET /config` loads the instance-effective configuration and redacts it before serialization at `packages/ax-code/src/server/routes/config.ts:153-155`. `PATCH /config` validates against `Config.Info`, removes recognized redaction sentinels, performs the merge/write, reloads the instance, and returns a newly loaded redacted view at lines 175-180. Sentinel stripping preserves existing provider secrets only when both the value is exactly `[redacted]` and the option name is secret-like at lines 18-27; remote MCP headers, OAuth client secrets, and local MCP environments have analogous handling at lines 53-71. The persistence layer locks, parses raw JSONC without resolving secret references, merges, writes, and reloads at `packages/ax-code/src/config/config-impl.ts:1434-1449`, avoiding stale or materialized-secret writes.

## Step 4 Evaluate Provider Enumeration and Cost

`GET /config/providers` obtains the cached provider registry once, maps `redactProviderInfo` over each entry, returns its values, and computes one sorted default model per provider at `packages/ax-code/src/server/routes/config.ts:204-210`. `Provider.list` is a cached instance-state read at `packages/ax-code/src/provider/provider-impl.ts:722-724`, while initialization deliberately starts independent config, model-catalog, and auth reads in parallel at lines 300-307. Request work is therefore proportional to provider count plus each provider's model sort; the route creates response copies but no unbounded queue, listener, timer, subprocess, or retry loop. The timing scope at `packages/ax-code/src/server/routes/config.ts:205` makes slow enumeration observable.

## Step 5 Assess Ownership and Contract Composition

HTTP/OpenAPI composition remains in `packages/ax-code/src/server/routes/config.ts:134-212`, request validation is delegated to the shared adapter at `packages/ax-code/src/server/validation.ts:4-13`, configuration persistence belongs to `Config.update` at `packages/ax-code/src/config/config-impl.ts:1434-1449`, and provider construction belongs to `packages/ax-code/src/provider/provider-impl.ts:404-488`. This separation is coherent. The main design weakness is that secret policy is implemented as route-local, shallow key heuristics at `packages/ax-code/src/server/routes/config.ts:16-37`, although both config provider options and runtime provider/model options are open records (`packages/ax-code/src/config/schema-impl.ts:557-582` and `packages/ax-code/src/provider/model-info.ts:54-72`). That mismatch makes the policy hard to keep complete as schemas evolve.

## Step 6 Review Failure Handling and Hygiene

Malformed PATCH bodies are converted to a 400 by the shared validation hook at `packages/ax-code/src/server/validation.ts:8-12`, and the route advertises that response at `packages/ax-code/src/server/routes/config.ts:172-175`. Persistence errors propagate to the server error envelope rather than being swallowed; project writes use in-process and cross-process locks at `packages/ax-code/src/config/config-impl.ts:1434-1448`. The candidate source contains no catch blocks, suppression directives, TODO/FIXME/HACK markers, or commented-out implementation. All five exports are reachable: the router is mounted at `packages/ax-code/src/server/server.ts:301`, global routes import both config helpers at `packages/ax-code/src/server/routes/global.ts:15`, and provider routes import `redactProviderInfo` at `packages/ax-code/src/server/routes/provider.ts:14`.

## Step 8 Reconcile Findings and Severity
