## Step 4 Performance and resource behavior

Response cardinality is bounded for all search routes: text search requests 10 hits at `packages/ax-code/src/server/routes/file.ts:44-48`, file search defaults to 10 and caps client input at 200 at lines 75–87, and the LSP wrapper uses a long RPC timeout plus a 10-symbol limit at `packages/ax-code/src/lsp/index-impl.ts:838-844`. File-name search reuses an initialized cache and slices results in `packages/ax-code/src/file/index.ts:753-778`. Text search invokes ripgrep as an argument array with `--` before the pattern, then validates JSON records and slices the final array in `packages/ax-code/src/file/ripgrep.ts:481-520`; `--max-count` limits each file rather than stopping the whole child process, so the HTTP response is bounded even though a very broad pattern can still make the lower-level search scan substantial project data. Status work uses a 32-worker pool for untracked-file reads rather than opening every file concurrently at `packages/ax-code/src/file/index.ts:556-589`. Directory listing is one-level, but text reads and full-context patch creation can scale with file size at lines 676–701; this is consistent with the local project-file API and is protected from request floods by the 600-per-minute GET bucket in `packages/ax-code/src/server/middleware.ts:54-80`.
