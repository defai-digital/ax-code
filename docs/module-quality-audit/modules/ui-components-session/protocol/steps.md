## Step 4 Request volume and render cost

One Medium concurrency concern remains in PR branch validation. `desktop/packages/ui/src/components/session/GitHubIntegrationDialog.tsx:224-263` caches only completed branch validations in React state, while the effect at `GitHubIntegrationDialog.tsx:265-274` depends on the callback whose identity changes with that map. Each completion can rerun the loop and launch duplicate checks for branches still in flight; the same unresolved checks can also commit after close because the post-await write has no request/open guard. Elsewhere, high-frequency work is bounded: notes save after a 400 ms debounce at `ProjectNotesTodoPanel.tsx:324-341`, sidebar search uses a 120 ms debounced query at `SessionSidebar.tsx:263-269`, and scheduled-task events coalesce reloads for 400 ms at `ScheduledTasksDialog.tsx:295-320`. The relative-time helper rounds before splitting units, avoiding boundary churn such as `1h 60m`, at `scheduledTaskRelativeTime.ts:27-46`.
