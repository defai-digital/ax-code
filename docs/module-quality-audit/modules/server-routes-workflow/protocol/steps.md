## Step 4 Error and status contracts

Validation failures are consistently converted to the shared 400 envelope by `packages/ax-code/src/server/validation.ts:4-12`. Missing runs are also sound: `WorkflowRun.getDetail` delegates to `getRun` (`packages/ax-code/src/workflow/run/index.ts:155-160`), which throws the storage `NotFoundError` at `packages/ax-code/src/workflow/run/internal.ts:166-173`; the global normalizer maps that named error to 404 (`packages/ax-code/src/server/error.ts:86-88`). Routine execution explicitly translates its two domain errors to 404 and 409 (`packages/ax-code/src/server/routes/workflow.ts:623-634`).

One Medium contract defect remains. Template endpoints advertise 404 (`workflow.ts:543`, `:560`), and template-backed run creation advertises 404 (`workflow.ts:209`), but `WorkflowTemplate.get` throws the plain `WorkflowTemplateNotFoundError` (`packages/ax-code/src/workflow/template.ts:115-126`, `:296-300`). The global plain-error branch has no workflow-template case and therefore returns `UnknownError`/500 (`packages/ax-code/src/server/error.ts:189-240`). This affects at least `GET /workflow-templates/:templateID`, promotion of a missing template, template-backed run creation through `WorkflowTemplate.createRun` (`packages/ax-code/src/workflow/template.ts:181-190`), and routine creation at `workflow.ts:605-606`. The fix belongs in error typing/normalization, plus an HTTP regression test.

## Step 5 Performance and data-volume behavior

The dashboard route performs one run-list query and then calls `WorkflowRun.getDetail` once per returned run in `Promise.all` (`packages/ax-code/src/server/routes/workflow.ts:252-262`). Each detail load reads phases, children, artifacts, and budget-ledger rows separately (`packages/ax-code/src/workflow/run/index.ts:159-190`). Because `limit` is optional in the route schema (`workflow.ts:53-57`) and the storage query only applies a limit when supplied (`run/index.ts:130-144`), a caller omitting it can trigger unbounded N+1-style work as durable run history grows. The shipping TUI consumer mitigates its own path by always requesting `limit=8` (`packages/ax-code/src/cli/cmd/tui/context/sync-runtime-sync.ts:125-127`). This is a Low performance advisory, not a release blocker for the local-only preview, but a server-side dashboard default would make the endpoint robust for all clients. Artifact filtering similarly loads the full run detail before filtering in memory (`workflow.ts:314-325`), acceptable for a single explicit run but worth monitoring for artifact-heavy histories.

## Step 6 Layering and schema design

The file generally keeps HTTP concerns local: Zod request/response declarations, OpenAPI metadata, status translation, and compact response shaping live in the route layer, while persistence and execution delegate to `WorkflowRun`, `WorkflowScheduler`, `WorkflowTemplate`, and `WorkflowRoutineTrigger` (`packages/ax-code/src/server/routes/workflow.ts:6-38`). Template saves are forcibly created as candidates regardless of an extra client field (`workflow.ts:514-530`), leaving trust promotion to the dedicated endpoint (`workflow.ts:549-565`). Routine execution also preserves domain ownership: `findApiRoutineTemplate` permits only enabled, trusted, local-only API routines (`packages/ax-code/src/workflow/routine.ts:183-196`). A maintainability wrinkle is that `WorkflowRoutineRunBody` duplicates the domain `RunInput` shape (`workflow.ts:106-112` versus `routine.ts:89-96`); they are aligned today, but exporting/reusing the domain schema would prevent future drift.
