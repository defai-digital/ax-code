## Step 3 Cross-contract correctness

Permission shapes align with the generated SDK: the local fields at `desktop/packages/ui/src/types/permission.ts:1-14` match `packages/sdk/js/src/v2/gen/types.gen.ts:577-603`. The question mirror does not: local `QuestionInfo` ends with `multiple?: boolean` at `desktop/packages/ui/src/types/question.ts:6-11`, whereas the SDK also carries `custom?: boolean` at `packages/sdk/js/src/v2/gen/types.gen.ts:653-674`. The UI consequently renders the custom-answer button unconditionally at `desktop/packages/ui/src/components/chat/QuestionCard.tsx:464-490`. This is observable for the plan-exit request, which explicitly sets `custom: false` and treats every answer other than `No` as consent to proceed at `packages/ax-code/src/tool/plan.ts:25-42`. Disposition: Medium correctness defect; preserve `custom`, hide the custom control when false, and cover that branch in a component test.

## Step 6 Ownership and maintainability

The strongest contracts derive from authoritative dependencies: `ProviderModel` indexes the SDK's provider model map and `ProviderWithModelList` changes only the collection representation at `desktop/packages/ui/src/types/providerModels.ts:1-4`; `SessionMessageRecord` similarly composes SDK `Message` and `Part` at `desktop/packages/ui/src/types/sessionMessages.ts:1-6`. Theme ownership is coherent but broad: required semantic foundations occupy `desktop/packages/ui/src/types/theme.ts:188-199`, while component extension maps remain optional at lines 200-239. `WorktreeMetadata` is appropriately UI-owned because it adds presentation and attachment state beyond the SDK worktree identity at `desktop/packages/ui/src/types/worktree.ts:14-48`.
