# Nine-step review protocol: runtime

## Step 1 Scope and public surfaces

The `runtime` review covered the 19 implementation files inventoried in `docs/module-quality-audit/modules/runtime/MODULE-AUDIT.md:20-44` and followed their direct tests and lifecycle callers. The module has three distinct surfaces: diagnostic catalogs and schemas (`packages/ax-code/src/runtime/debug-snapshot.ts:49-80`, `packages/ax-code/src/runtime/failure-class.ts:48-93`, and `packages/ax-code/src/runtime/hot-path.ts:148-199`), process/server helpers (`packages/ax-code/src/runtime/listen-security.ts:1-53`, `packages/ax-code/src/runtime/local-client.ts:7-28`, and `packages/ax-code/src/runtime/shell-env.ts:45-105`), and the headless command/event/projection stack exported by `packages/ax-code/src/runtime/headless/index.ts:1-9`. `packages/ax-code/src/runtime/service-manager.ts:360-539` owns the remaining public lifecycle API.

## Step 2 Trust boundaries and sensitive data

Network exposure is fail-closed: non-loopback binds throw at `packages/ax-code/src/runtime/listen-security.ts:27-31`, and attach URLs must be HTTP(S) plus a loopback hostname at `packages/ax-code/src/runtime/listen-security.ts:34-44`. The in-process client applies runtime authentication before dispatch at `packages/ax-code/src/runtime/local-client.ts:12-27`. Autonomous mode explicitly leaves isolation-escalation and destructive-shell permissions pending at `packages/ax-code/src/runtime/headless/projection.ts:110-119`. Raw headless records are serialized wholesale at `packages/ax-code/src/runtime/headless/event-log.ts:10-26` and can be persisted by `packages/ax-code/src/runtime/headless/event-sink-node.ts:6-17`; because message and request payloads may be present, event-log files should be treated as sensitive user data even though logging is opt-in.

## Step 3 State-machine correctness

Projection updates are exhaustive over the typed event union at `packages/ax-code/src/runtime/headless/projection.ts:99-261`, and session deletion clears requests, status, errors, goals, messages, parts, and session-scoped queue entries at `packages/ax-code/src/runtime/headless/projection.ts:330-361`. Two residual correctness risks were identified. First, event decoding checks only membership of the `type` string (`packages/ax-code/src/runtime/headless/event.ts:167-176`), while replay immediately applies the asserted payload (`packages/ax-code/src/runtime/headless/replay.ts:71-76`), so a malformed known-type record can throw inside the projection instead of being rejected at the decode boundary. Second, a service timeout aborts only the supplied signal at `packages/ax-code/src/runtime/service-manager.ts:257-274` but still awaits the task at `packages/ax-code/src/runtime/service-manager.ts:279-300`; project discovery ignores that signal at `packages/ax-code/src/project/instance.ts:127-136`, so its nominal 10-second timeout emits diagnostics without bounding bootstrap latency.

## Step 4 Errors, cancellation, and resource closure

The headless runner links the caller signal to an internal controller and removes the listener in its outer `finally` (`packages/ax-code/src/runtime/headless/runner.ts:82-87` and `packages/ax-code/src/runtime/headless/runner.ts:125-131`). Command failures abort and join the subscription before rethrowing at `packages/ax-code/src/runtime/headless/runner.ts:117-123`, and sinks close on all exits. File writes honor backpressure through drain/error listeners at `packages/ax-code/src/runtime/headless/event-sink-node.ts:20-38`, while close waits for finish or error at `packages/ax-code/src/runtime/headless/event-sink-node.ts:41-60`. One hardening gap remains: a write that returns `true` installs no error listener, so an asynchronous stream-open/write error can escape before `close()` attaches one. Shell environment capture does release pipes and unref a stuck child at `packages/ax-code/src/runtime/shell-env.ts:23-41`.

## Step 5 Bounded work and hot-path pressure

Headless message retention defaults to 100 entries per session and deletes parts for evicted messages (`packages/ax-code/src/runtime/headless/projection.ts:363-382` and `packages/ax-code/src/runtime/headless/projection.ts:438-442`). Sorted binary upserts at `packages/ax-code/src/runtime/headless/projection.ts:321-328` avoid full scans for lookup, although array insertion remains linear. The service registry is capped at 256 directories and preferentially evicts inactive entries at `packages/ax-code/src/runtime/service-manager.ts:10-12` and `packages/ax-code/src/runtime/service-manager.ts:29-68`; terminal task rows are pruned after the per-state map exceeds 1,000 at `packages/ax-code/src/runtime/service-manager.ts:201-221`. Workflow events each enqueue an immediate probe at `packages/ax-code/src/runtime/headless/projection.ts:232-257`, and effects are launched without coalescing at `packages/ax-code/src/runtime/headless/effects.ts:61-66`, leaving probe storms as a performance watch item.

## Step 6 Ownership and dependency shape

The headless design separates transport commands (`packages/ax-code/src/runtime/headless/runtime.ts:51-127`), event recognition (`packages/ax-code/src/runtime/headless/event.ts:103-176`), pure state mutation (`packages/ax-code/src/runtime/headless/projection.ts:79-262`), side effects (`packages/ax-code/src/runtime/headless/effects.ts:28-78`), and orchestration (`packages/ax-code/src/runtime/headless/runner.ts:69-135`). That split supports deterministic replay because replay clones each event before mutation at `packages/ax-code/src/runtime/headless/replay.ts:82-90`. `RuntimeLocalClient` deliberately couples runtime code back to server implementation through imports at `packages/ax-code/src/runtime/local-client.ts:1-5`; it is an in-process adapter rather than a transport-neutral primitive. The hot-path file is descriptive inventory, with immutable parsed entries and defensive copies at `packages/ax-code/src/runtime/hot-path.ts:183-199`, not a lifecycle executor.

## Step 7 Maintainability and contract drift

No TODO/FIXME directives or suppression comments were present in the reviewed runtime sources. The only broad casts are SDK request-shape bridges for permission and question replies at `packages/ax-code/src/runtime/headless/runtime.ts:84-88`; stronger generated SDK input typing would remove them. The catch blocks at `packages/ax-code/src/runtime/listen-security.ts:34-52` intentionally translate invalid input into a stable error or `null`, rather than hiding an operational failure. A drift hazard exists because event names are declared both in unions at `packages/ax-code/src/runtime/headless/event.ts:5-101` and again in the manual allow-list at `packages/ax-code/src/runtime/headless/event.ts:107-165`; adding an event to only one location can make valid traffic disappear or weaken exhaustiveness assumptions.
