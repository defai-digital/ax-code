## Step 1 Scope and map

It is mounted exactly once, under the `/experimental` prefix, in `packages/ax-code/src/server/server.ts:312` (`.route("/experimental", ExperimentalRoutes())`). ## Step 2 Threat and failure model

The risk tags `network, api` are justified: every handler either reads from or mutates project/worktree/session state over HTTP. Three concrete trust boundaries: (1) `DELETE /worktree` (`experimental.ts:167-174`) takes a client-supplied `body.directory`, resolves it through `canonicalSandboxDirectory`, and then both removes the worktree and calls `Project.removeSandbox` — a deletion + sandbox-registry mutation driven by request input. (2) `GET /session` (`experimental.ts:201-258`) calls `Session.listGlobal` which, per `session/index.ts:652-704`, returns rows across all projects when no directory filter is active; the route documents a `directory` filter but (see Step 3) does not honor its value. (3) `POST /worktree` (`experimental.ts:120-125`) runs configured startup scripts inside the new worktree per the operation description at line 106. Input validation is delegated to the `validator` wrapper in `server/validation.ts:4-13`, which converts failed Zod parses into a 400 via `invalidRequest`. No empty `catch` blocks exist in this file (the only `.catch` is the intentional realpath fallback at `experimental.ts:21`).

## Step 3 Correctness

The dominant correctness defect is in the `/session` handler. The route declares a `directory` query param with the description "Filter sessions by project directory" (`experimental.ts:222`), but the handler maps it as `directory: query.directory ? Instance.directory : undefined` (`experimental.ts:242`). This discards the client-provided value entirely: any truthy `directory` substitutes the _current_ project's directory (`Instance.directory`) rather than the requested one. A caller asking for sessions of project B from a server rooted in project A will silently receive project A's sessions (or none) instead of an error. The downstream `Session.listGlobal` at `session/index.ts:674-676` does honor `parsed.directory` correctly, so the bug is local to this route's argument shaping. Secondary correctness note: `canonicalSandboxDirectory` is applied only on `DELETE /worktree` (`experimental.ts:170`) before `Project.removeSandbox`; the `POST /worktree` create path performs no such canonicalization at this layer, so the key shape stored by create (inside `Worktree.create`, `worktree/index-impl.ts:618`) and the key shape removed by delete can diverge across symlinks/casing — worth verifying against `Project.addSandbox`/`removeSandbox` key semantics.

## Step 4 Performance

`GET /session` implements cursor pagination with the standard `limit + 1` probe (`experimental.ts:247`, `limit` defaulting to 100 at line 239, capped at 1000 by the Zod bound at line 231). The `hasMore` short-circuit and `x-next-cursor` header emission keyed on `list[list.length - 1].time.updated` (line 254) are correct given `Session.listGlobal` orders by `desc(time_updated), desc(id)` (`session/index.ts:703`). One concern: `Session.listGlobal` is a generator that the handler spreads into an array (`experimental.ts:240-250`); combined with the inner `Database.use` queries in `session/index.ts:695-710` this is at least two round trips per request (sessions + projects) — acceptable for a local server but not free. `GET /tool` (`experimental.ts:89-100`) calls `zodToJsonSchema(t.parameters)` per tool on every request with no caching; for large tool catalogs this recomputes JSON schemas each call. No N+1 loops were found in this file.

## Step 5 Design and ownership

The route module is appropriately thin: it validates, delegates to domain modules (`ToolRegistry`, `Worktree`, `Project`, `Instance`, `MCP`, `Session`), and serializes. It does not reach into storage or provider internals directly, which is the right layering for a `server/routes/*` file. The `ExperimentalRoutes` lazy singleton mirrors sibling modules and is mounted once (`server.ts:312`). The `/experimental` prefix is the correct namespace given the mixed, evolving surface (global session listing alongside worktree CRUD and MCP resource listing). One design smell: the file mixes three fairly distinct resource families (tools, worktrees, sessions+resources) behind one router; if `/experimental` grows further, splitting into `experimental/tools`, `experimental/worktrees`, `experimental/sessions` sub-routers would improve discoverability — but at 280 lines and 7 routes this does not yet warrant extraction (below the 3+ distinct-call-site bar for a structural change).
