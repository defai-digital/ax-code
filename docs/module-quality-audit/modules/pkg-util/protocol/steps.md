# 9-Step Review: pkg-util

This review examined every candidate source, the package metadata and architecture note, the existing module audit, the finding ledger, and representative consumers/tests. Citations below identify evidence read during this pass.

## Step 1 Scope and public surface

`pkg-util` is a private wildcard-exported package: `packages/util/package.json:2-8` exposes each `src/*.ts` module as `@ax-code/util/*`. Its stated purpose is small, broadly reusable, dependency-light helpers (`packages/util/ARCHITECTURE.md:5-14`). The surface spans collection primitives (`src/array.ts:1-10`, `src/binary.ts:1-40`), encoding/checksums (`src/encode.ts:1-52`), typed errors and schema-bound callbacks (`src/error.ts:3-58`, `src/fn.ts:3-10`), identifiers and labels (`src/identifier.ts:3-66`, `src/slug.ts:1-73`), evaluation/cache helpers (`src/iife.ts:1-3`, `src/lazy.ts:1-14`), module/path handling (`src/module.ts:1-9`, `src/path.ts:1-39`), and retry policy (`src/retry.ts:1-40`). `packages/util/sst-env.d.ts:1-9` is generated declaration plumbing rather than runtime behavior.

## Step 2 Trust boundaries and failure modes

The only direct filesystem-resolution boundary is `Module.resolve`, which derives a `createRequire` anchor from caller-provided `dir` and resolves caller-provided `id` (`packages/util/src/module.ts:5-8`). Callers use its `undefined` outcome to skip unavailable language servers, for example `packages/ax-code/src/lsp/server-helpers.ts:48-58` and `packages/ax-code/src/lsp/server-defs/web-servers.ts:101-103`; no file is executed in this helper itself. Cryptographic hashing uses `crypto.subtle.digest` (`packages/util/src/encode.ts:14-20`), while `checksum` is explicitly a compact FNV-style value (`encode.ts:23-30`) and should not be treated as an authenticity primitive. Identifier entropy uses rejection-sampled `randomBytes` (`packages/util/src/identifier.ts:21-37`), whereas `Slug.create` uses `Math.random` over a small adjective/noun space (`src/slug.ts:68-72`); session creation uses that slug only as metadata at `packages/ax-code/src/session/index.ts:427-439`, so it must not become an authorization token or uniqueness key.

## Step 3 Correctness and edge cases

Most straight-line behavior is sound: binary lookup returns the lower insertion point when absent (`packages/util/src/binary.ts:3-19`), `lazy` marks its cache loaded only after a synchronous return (`src/lazy.ts:5-12`), and retry rethrows either a non-transient error or the final failure (`src/retry.ts:30-38`). Two concrete Low-level gaps emerged. First, `NamedError.isInstance` evaluates `"name" in input` after only checking `typeof input === "object"` (`src/error.ts:29-30`), so `isInstance(null)` throws instead of returning false. Second, the last sample point is `content.length - size` (`src/encode.ts:43`), but the common centering formula subtracts another half-window (`encode.ts:47-49`); the final 2,048 characters are therefore never represented in a large-content sampled checksum. Additional boundary behavior is undocumented: `getDirectory("file")` produces `/` via the unconditional suffix at `src/path.ts:8-13`, and non-positive `maxLength` values still emit an ellipsis at `path.ts:22-29,32-38`. None of these observations is Critical, but each merits a focused regression test before the helper is adopted more broadly.

## Step 4 Performance and resource use

The intended hot paths are bounded. `Binary.search` is O(log n) (`packages/util/src/binary.ts:3-17`), while `Binary.insert` performs a logarithmic position search followed by the expected O(n) array splice (`binary.ts:22-39`). For content over the threshold, `sampledChecksum` hashes five fixed 4,096-character slices rather than scanning the whole input (`packages/util/src/encode.ts:33-51`); this is efficient, subject to the coverage gap in Step 3. `randomBase62` oversamples two bytes per requested character and rejects bytes 248-255 (`src/identifier.ts:21-35`), giving unbiased output with low expected retry cost. `retry` bounds both attempts and exponential delay (`src/retry.ts:26-37`), though invalid options such as `attempts <= 0` are not validated and reach `throw lastError` with no captured error (`retry.ts:29-40`). Base64 conversion materializes a byte array, a character array, and a joined string (`encode.ts:1-4`), acceptable for small utility inputs but not a streaming interface for large payloads.

## Step 5 Design and ownership

The package generally matches its generic-helper charter (`packages/util/ARCHITECTURE.md:5,13-14`) and keeps its sole external runtime dependency to Zod (`packages/util/package.json:13-15`). One ownership seam has drifted: `packages/util/src/identifier.ts:5-66` contains a complete monotonic ID generator, while `packages/ax-code/src/id/id.ts:40-101` independently implements nearly the same counter, timestamp packing, rejection sampling, and random suffix. The core module imports only `BASE62_ALPHABET` from the package (`packages/ax-code/src/id/id.ts:1-3`), so fixes such as clock rollback/counter-wrap handling present at `packages/util/src/identifier.ts:40-54` do not automatically propagate to the product generator. Consolidating the common encoder or narrowing the package export to the shared alphabet would make ownership explicit. The package also mixes Node-only primitives (`randomBytes` and `Buffer` at `src/identifier.ts:1,60`) with Web globals (`btoa`, `atob`, and `crypto.subtle` at `src/encode.ts:4,9,17`); that is workable under the declared Node environment, but it is not a portable browser utility contract.

## Step 6 Dead code and maintenance hygiene

Repository consumers directly exercise only part of the wildcard surface: `NamedError` is imported widely, `Binary` backs sorted projection state (`packages/ax-code/src/runtime/headless/projection.ts:1-3`), `lazy` defers PTY addon loading (`packages/ax-code/src/pty/index.ts:207-213`), and `Module.resolve` supports LSP discovery (`packages/ax-code/src/lsp/server-helpers.ts:48-58`). By contrast, the repository import scan found no `@ax-code/util/*` consumers for `array.ts`, `encode.ts`, `fn.ts`, `iife.ts`, `path.ts`, or `retry.ts`; because `package.json:7-9` publishes them anyway, they are dormant internal API rather than proven dead code. The one empty catch is `packages/util/src/module.ts:6-8`. Its `undefined` fallback is expected for a missing optional package, as asserted at `packages/ax-code/test/util/module.test.ts:55-58`, but it also erases malformed-package and permission errors. The existing finding correctly keeps this site visible pending either a narrow error filter or a local best-effort comment. The generated warning in `packages/util/sst-env.d.ts:1-5` is respected; that file should not be hand-maintained.
