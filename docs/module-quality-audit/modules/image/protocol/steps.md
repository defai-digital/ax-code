## Step 1 Map the module and its boundaries

The `image` unit is the provider-adapter layer under `packages/ax-code/src/image`. Its barrel exposes the factory and four contracts at `packages/ax-code/src/image/index.ts:1-7`; the concrete OpenAI, Stability, and custom implementations live at `packages/ax-code/src/image/provider.ts:42`, `:93`, and `:133`. The provider layer owns HTTP request/response translation but not permissions, filesystem output, or attachment creation; those remain in the tool at `image_gen.ts:90-155`.

## Step 2 Model threats and failures

## Step 3 Trace correctness and lifecycle paths

OpenAI selects DALL-E compatibility only for `dall-e-2`/`dall-e-3`, sending `response_format`; newer models request `output_format` at `packages/ax-code/src/image/provider.ts:59-67`, then require `data[0].b64_json` and derive PNG/JPEG/WebP at `:81-89`. Stability builds multipart input and derives an aspect ratio at `:108-129`. The normal tool path constrains sizes with a Zod enum at `packages/ax-code/src/tool/image_gen.ts:21` and `:85-89`, but the exported Stability class itself accepts any string through `ImageGenerateInput.size` (`provider.ts:6-11`); malformed direct-call values can reach recursive `normalizeAspectRatio` at `:186-190`. Custom responses prefer base64 and otherwise fetch the returned URL at `:166-182`. The factory selection is deterministic: explicit provider wins, an unspecified provider plus `baseURL` selects custom, Stability is auto-selected only when its key exists without an OpenAI key, and all other cases select OpenAI (`:192-208`). Providers hold no timers or handles, and AbortSignal ownership stays with the caller.

## Step 4 Review performance and resource bounds

Each generation performs one request, except a custom URL result, which performs a second download (`packages/ax-code/src/image/provider.ts:150-180`). There is no retry loop or N+1 behavior. Responses are materialized in full by `response.json`, `response.arrayBuffer`, or base64 decoding at `:81-89`, `:128-129`, `:166-180`; the tool subsequently creates another base64 representation for its data-URI attachment at `packages/ax-code/src/tool/image_gen.ts:132-155`. Neither layer enforces a response-byte cap, so a misbehaving configured endpoint can amplify memory use; this is a hardening candidate at the provider trust boundary, not a measured performance finding. Provider construction is cached by `JSON.stringify(imageCfg)` at `image_gen.ts:25-35`, avoiding repeated setup while replacing the instance when configuration changes. The tool supplies a five-minute deadline and clears its timer in `finally` at `:119-130`.

## Step 5 Assess design and ownership

The adapters are cohesive: they normalize three wire formats behind `ImageProvider.generate` (`packages/ax-code/src/image/provider.ts:18-21`), while selection stays in `createImageProvider` at `:192-203`. SSRF policy is delegated to the shared network utility instead of duplicated (`:171-176`), and write isolation, permission prompts, collision-safe output, and blast-radius accounting remain in `packages/ax-code/src/tool/image_gen.ts:49-80` and `:90-112`. The schema and TypeScript config shapes align: the provider enum and `apiKey`/`baseURL`/`model` fields at `packages/ax-code/src/config/schema-impl.ts:1060-1077` correspond to `provider.ts:23-30`. The public input includes `name` at `provider.ts:6-10`, but none of the adapters uses it; the tool passes it at `image_gen.ts:122-127`. That is mild contract noise rather than dead behavior because it may support provider-specific naming through future adapters.

The barrel intentionally omits the three concrete classes while tests import them directly from `packages/ax-code/src/image/provider.ts:2`; production code consumes the factory through `packages/ax-code/src/image/index.ts:1-7`. No TODO/FIXME/HACK markers, commented-out implementations, unsafe suppressions, or empty catch blocks occur in the candidate source. The three `.catch(() => "")` sites at `provider.ts:78`, `:125`, and `:163` are narrow error-body fallbacks and do not suppress the primary non-2xx failure, which is thrown immediately afterward.
