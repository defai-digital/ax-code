## Step 2 Data, mutation, and failure boundaries

The highest-impact boundary is permission approval. `desktop/packages/ui/src/stores/permissionStore.ts:262-289` changes local auto-accept state and mirrors suppression to the notification endpoint, while `permissionStore.ts:314-365` gathers pending requests, checks ancestry, rechecks the live toggle, and invokes `respondToPermission`. Configuration stores send user-authored agent and command bodies to local API endpoints at `useAgentsStore.ts:275-295,344-365` and `useCommandsStore.ts:232-253,304-325`. SSH actions are delegated to the desktop bridge at `useDesktopSshStore.ts:184-250`. Persisted queue entries include message content and attachment metadata (`messageQueueStore.ts:7-19,166-172`), whereas agent and command persistence is limited to the selected name (`useAgentsStore.ts:457-463`; `useCommandsStore.ts:418-424`). Best-effort notification failures are intentionally swallowed at `permissionStore.ts:281-289,419-429`; approval calls themselves are awaited.

## Step 3 Selection and cache correctness

Pagination is bounded by empty/partial pages, cursor monotonicity, and duplicate IDs at `desktop/packages/ui/src/stores/globalSessions.ts:68-113`. Queue mutation removes empty per-session keys and enforces a 50-entry ceiling at `messageQueueStore.ts:60-95,136-154`. A High cross-project correctness defect exists in both configuration-editor stores: freshness timestamps are keyed by directory (`useAgentsStore.ts:28-32`; `useCommandsStore.ts:38-42`), but each store holds only one global result array (`useAgentsStore.ts:104-108`; `useCommandsStore.ts:63-67`). After loading A, then B, returning to A inside the five-second TTL makes the early return at `useAgentsStore.ts:138-147` or `useCommandsStore.ts:95-104` retain B's list. The request-sequence guards at `useAgentsStore.ts:154-156,220-227` and `useCommandsStore.ts:111-115,178-186` prevent an older overlapping response from committing, but they do not restore a directory-specific cached value.

## Step 4 Concurrency and lifecycle behavior

Permission enabling is protected against a disable during asynchronous gathering: the live map is checked before each response at `desktop/packages/ui/src/stores/permissionStore.ts:351-365`, and the regression is exercised at `permissionStore.test.ts:90-104`. SSH state merges by `updatedAtMs` and filters removed instance IDs at `useDesktopSshStore.ts:52-104,117-143,166-178`; its four race/removal cases appear at `useDesktopSshStore.test.ts:85-148`. By contrast, `useAgentGroupsStore.loadGroups` captures the current project, awaits worktree/session IO, and commits unconditionally at `useAgentGroupsStore.ts:203-277`. The view deliberately reloads on directory changes at `desktop/packages/ui/src/components/views/agent-manager/AgentManagerView.tsx:17-37`, so a slower request for the prior directory can overwrite the newer groups. That is a Medium stale-completion risk; the store needs a project key or request generation check.

## Step 5 Work bounds and performance

Several potentially growing paths are explicitly limited: queue length is capped at 50 (`desktop/packages/ui/src/stores/messageQueueStore.ts:40-41,63-67`), worktree session fetches run through at most five workers (`useAgentGroupsStore.ts:230-259`), and session pagination stops when IDs or cursors stop advancing (`globalSessions.ts:97-113`). `buildGroups` repeatedly searches the full raw session list while reducing every group at `useAgentGroupsStore.ts:142-148`, making grouping quadratic in the number of sessions; this is Low unless agent-group cardinality grows substantially. Provider startup handling is intentionally expensive: each directory can make twelve attempts with a ten-second per-request timeout and increasing waits before scheduling more polling (`useConfigStore-impl.ts:516-529,738-880`). Timer dedup prevents fan-out, but the long tail should remain observable because a genuinely unavailable backend can keep a caller in loading state for a prolonged period.

## Step 6 Ownership, persistence, and hygiene

The store architecture guide reserves this directory for shared, cache-like, or imperatively updated state at `desktop/packages/ui/src/stores/DOCUMENTATION.md:3-16` and requires identity-keyed caches plus stable references at `DOCUMENTATION.md:105-150`. `useConfigStore-impl.ts:679-736,783-843` follows that model with directory snapshots and active-key checks, while the agent/command editor stores violate it through their key/list mismatch identified in Step 3. Agent and command CRUD loaders also duplicate substantial directory, retry, scope-detection, reload, and persistence logic (`useAgentsStore.ts:138-468`; `useCommandsStore.ts:95-430`), raising drift risk. Repository search found the exported helpers `readNextCursor` and `isMissingGlobalSessionsEndpointError` only at their definitions in `globalSessions.ts:40-58`; the paginator bypasses `readNextCursor` at `globalSessions.ts:102`, so both are dead public surface candidates. No TODO or FIXME marker was present in the reviewed candidates.

They cover queue pruning/capping (`desktop/packages/ui/src/stores/messageQueueStore.test.ts:9-30`), permission enable/disable ordering and pruning (`permissionStore.test.ts:77-117`), overlapping agent and command loads (`useAgentsStore.test.ts:132-162`; `useCommandsStore.test.ts:89-119`), monotonic SSH events (`useDesktopSshStore.test.ts:85-148`), and persisted desktop-surface validation (`useDesktopSurfaceStore.test.ts:9-30`).
