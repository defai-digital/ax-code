## Step 2 Threat and Failure Model

This command shells out to `pgrep` (`doctor-health.ts:42`) and probes a TCP port with a raw socket (`doctor.ts:451–466`). The `pgrep` call is a fixed literal argv (no interpolation), so command injection is not possible; the result is parsed defensively with `parseDecimalPid` (`doctor-health.ts:25`) which rejects non-numeric PIDs. The port probe connects to a hard-coded `127.0.0.1` (never to the user-supplied hostname), which is the correct local-only posture. The biggest failure-mode risk is silent swallowing: every external dependency (`Config.get`, `Auth.all`, `ModelsDev.get`, `Config.global`, `getAxEngineStatus`) is wrapped in try/catch that degrades to a best-effort check rather than crashing the whole report — see the credentials catch at line 300, the models.dev catch at 316, the server-exposure fallback at 373, the isolation fallback at 390, the ax-engine catch at 426, and the TUI-server outer catch at 476. No credentials are printed in detail; the credentials check (lines 290–341) emits only provider IDs and env-var names, never values, which is the right redaction posture.

## Step 3 Correctness

`getServerExposureCheck` (line 52) is correct and self-consistent: a non-loopback requested hostname is reported as ignored and the effective hostname forced back to `127.0.0.1` (line 55, line 62). `getIsolationPolicyCheck` (line 66) correctly resolves precedence `envMode → config.mode → default` and forces `network=true` under `full-access`. `getAxEngineDoctorCheck` (line 91) has many return paths but each guards a distinct condition (not-supported → dependency missing → disk not ok → model not present → phase error/degraded → ready); tracing the branches they are mutually exclusive and the fallthrough at line 148 returns `ok` only when `status.server.ready || phase === "ready"`. One real correctness concern: at `doctor.ts:451` the ESM source uses `const net = require("net")`. This package is `"type": "module"`, so in source/dev mode `require` is not defined on the global scope and the inner Promise executor throws `ReferenceError: require is not defined`; that is swallowed by the outer catch at line 476, which then pushes a generic `status:"ok" / "Port ${tuiPort} available"` (line 477). Net effect: in source/dev mode the port-conflict detection silently always reports "ok". In the esbuild-bundled CLI the `require` is shimmed, so packaged runs work — which explains why the bug is latent. See Step 8 F-1.

## Step 4 Performance

`doctor` is a low-frequency interactive diagnostic, so latency is not safety-critical, but the handler is fully sequential. Independent checks that touch the filesystem or network — `doctorProjectContext` (three ancestor walks at lines 214–223), the TUI liveness `fetch` with a 1500ms timeout (line 436–440), the port-blocked socket probe (1000ms timeout, line 453), `NativeAddon.index/fs/diff/parser` loads (lines 403–407), the `pgrep` subprocess (5s timeout in `doctor-health.ts:15`) and the recent-logs scan (`doctor-health.ts:75`, reads up to 5 files) — all run one after another. Worst case the user can wait on the sum of every timeout. A bounded `Promise.all` over the independent probes would cut typical wall time substantially. Not blocking, not a finding, but the single biggest perf lever in the file. The `seenEnv` dedup (line 308) keeps the credential env scan O(providers × envs) with no quadratic blow-up.

## Step 5 Design and Ownership

Orchestration in `doctor.ts`, heavy checks in sidecar files, is a good split — each sidecar exports its own `DoctorCheck` type and accepts injectable seams (`inspect`, `run`, `readFile`, `readdir`, `stat`, `resolveSync`) for testability. The duplicated local `DoctorCheck` type definition in all four files (`doctor.ts:36`, `doctor-storage.ts:6`, `doctor-health.ts:6`, `doctor-preload.ts:7`) is mild duplication; it is structurally identical and a single shared type would remove drift risk, but the cost is low and the type is tiny. The exported pure helpers (`getRuntimeCheck`, `getServerExposureCheck`, `getIsolationPolicyCheck`) are correctly side-effect-free, which makes them unit-testable without mocks — the right shape. `getServerExposureCheck` always returns `status:"ok"` (line 59) even when the user asked for a non-loopback bind that the policy silently overrode; reporting that as a `warn` would surface the override to users who wonder why their `--hostname 0.0.0.0` "doesn't work", but this is a UX judgment, not a defect.

## Step 8 Findings Register

F-1 (MEDIUM) — `require("net")` in an ESM file silently breaks port-conflict detection in source/dev mode. Location: `packages/ax-code/src/cli/cmd/doctor.ts:451`. In source/dev mode the package runs as native ESM where `require` is undefined; the thrown `ReferenceError` is swallowed by the outer catch at line 476, which then unconditionally pushes `status:"ok", detail:"Port ${tuiPort} available"` (line 477). The packaged CLI hides this because esbuild shims `require`. Recommended fix: hoist `import net from "node:net"` to the top of the module and drop the inline `require`; this works in both ESM and bundled output and lets the `portBlocked` branch (lines 450–466) actually run.

F-2 (LOW) — Inline check-numbering comments have drifted. Location: `packages/ax-code/src/cli/cmd/doctor.ts:434, 480` (two `11b`), `484, 487` (two `12`), plus the missing `11a`. Cosmetic only; output is unaffected because the `// Print results` loop at line 533 iterates `checks` by value, not by label. Recommended fix: delete the leading `// N.` numbers from each block or renumber them sequentially.

F-3 (LOW) — Duplicated `DoctorCheck` type literal across four files (`doctor.ts:36`, `doctor-storage.ts:6`, `doctor-health.ts:6`, `doctor-preload.ts:7`). Structurally identical; a single shared `DoctorCheck` (e.g. from `doctor-storage.ts` or a small `doctor-types.ts`) would remove drift risk. Per the duplication-over-abstraction rule, two copies are tolerable — four identical copies across sibling files clears the bar for a single extraction.

No Critical findings; reverify.md is therefore not required for this unit.
