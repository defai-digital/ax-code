## Step 2 Data and trust boundaries

Permission request data includes arbitrary tool names and patterns (`desktop/packages/ui/src/types/permission.ts:1-11`). The watcher limits the preview to two nonempty patterns and joins them as plain text at `desktop/packages/ui/src/components/notifications/PermissionNotifications.tsx:71-80`; the center renders titles and messages through normal React text nodes at `desktop/packages/ui/src/components/notifications/NotificationCenter.tsx:45-48`, so request text is escaped rather than interpreted as markup. No credential, shell, or raw-HTML sink was found in the reviewed path.

## Step 3 Mirroring and removal correctness

The pure diff computes additions by request ID, builds a live-ID set, and emits stored notification IDs only for requests that disappeared (`desktop/packages/ui/src/components/notifications/permissionNotificationSync.ts:17-29`). `SessionPermissionWatcher` applies removals before additions and updates its request-to-notification map in lockstep at `desktop/packages/ui/src/components/notifications/PermissionNotifications.tsx:52-83`. Its unmount cleanup removes all remaining mirrored items and clears the map (`PermissionNotifications.tsx:86-97`), preventing notifications from surviving a closed session. The focused suite pins new additions, removal of one stale request, preservation of one existing request while adding another, and full removal for an empty pending list at `desktop/packages/ui/src/components/notifications/permissionNotificationSync.test.ts:15-49`. This ID-based reconciliation is deterministic and does not depend on object identity inside the helper.

## Step 4 Permission action and error lifecycle

A Medium correctness defect exists in the actionable center. Both buttons invoke their callback and immediately remove the item (`desktop/packages/ui/src/components/notifications/NotificationCenter.tsx:49-69`). The callback starts `respondToPermission` without returning its promise; on rejection it only logs and shows a toast (`desktop/packages/ui/src/components/notifications/PermissionNotifications.tsx:63-69`). The request therefore remains pending, but `mirroredNotificationIdsRef` still records it as mirrored (`PermissionNotifications.tsx:46-47,82`), so a later diff will not add it again (`desktop/packages/ui/src/components/notifications/permissionNotificationSync.ts:21`). This conflicts with the retry behavior used by the chat permission card, which awaits the reply, resets its synchronous submission guard, and keeps the action available on failure (`desktop/packages/ui/src/components/chat/PermissionCard.tsx:94-117`). The center should await success before removal, retain/recreate the item on failure, and guard double submission.

## Step 5 Focus, debounce, and attention state

Native notification delivery is suppressed while the relevant session is focused, then rechecked after a two-second debounce (`desktop/packages/ui/src/components/notifications/PermissionNotifications.tsx:16-24,99-126`). Dependency changes cancel the timer, and `notifiedRef` resets only after the session has no pending permissions (`PermissionNotifications.tsx:99-105`), which correctly treats overlapping requests as one continuous waiting episode. `AttentionBadgeSync` mirrors the number of affected sessions rather than the number of requests and resets both the web attention store and native badge on unmount (`PermissionNotifications.tsx:131-154`). In the center, closing through the backdrop or Escape updates the same store (`desktop/packages/ui/src/components/notifications/NotificationCenter.tsx:103-130`); the separate transition effect then marks all items read only after the panel closes (`NotificationCenter.tsx:89-101`), preserving the unread badge during inspection.

## Step 6 Rendering cost and time behavior

The store caps retained notifications at 100 when inserting (`desktop/packages/ui/src/stores/useNotificationStore.ts:43-53`), and the center's unread reduction and item render are therefore bounded. Permission reconciliation is linear in pending plus mirrored requests because it creates one `Set` and walks each collection once (`desktop/packages/ui/src/components/notifications/permissionNotificationSync.ts:21-28`). `PermissionNotifications` intentionally creates one watcher per live session (`desktop/packages/ui/src/components/notifications/PermissionNotifications.tsx:164-177`), so subscriptions scale with live sessions but each watcher performs bounded per-session work. One Low display issue remains: `timeLabel` samples `Date.now()` only inside a memo keyed by `item.timestamp` and `t` (`desktop/packages/ui/src/components/notifications/NotificationCenter.tsx:23-31`). An open, otherwise idle panel can continue showing “just now” or an obsolete minute count until another render occurs; a shared minute tick while open would keep labels accurate without per-row timers.

## Step 7 Design, accessibility, and code hygiene

The separation between the pure diff and effectful React watcher is sound: `permissionNotificationSync.ts:17-29` imports only the permission type, while store, runtime API, session action, and toast effects remain in `PermissionNotifications.tsx:1-14`. User-facing strings are localized; the keys used by both components exist at `desktop/packages/ui/src/lib/i18n/messages/en.ts:2439-2441,2672-2686`. The panel provides `role="dialog"`, a localized label, programmatic focus, Escape close, and focus restoration (`desktop/packages/ui/src/components/notifications/NotificationCenter.tsx:103-138`). However, its backdrop makes it behave modally while the dialog lacks `aria-modal` and a focus trap, so keyboard users can tab into obscured page controls; this is a Low accessibility gap. Across the four candidate files there are no TODO/FIXME markers, suppressed exceptions, unsafe casts, or commented-out implementations; the explicit async catches in `PermissionNotifications.tsx:64-69` expose failures through both logging and a toast.
