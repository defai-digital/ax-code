## Step 2 Trust Boundaries and Secret Handling

Capability probes do not use a shell: `spawnExitsCleanly` passes an argument array and a sanitized environment at `packages/ax-code/src/mcp/discovery.ts:41-62`, backed by the array-based `cross-spawn` call at `packages/ax-code/src/util/process.ts:108-119` and credential filtering at `packages/ax-code/src/util/env.ts:64-82`. The only discovery network request targets a fixed HTTPS endpoint, has a three-second abort, and cancels its body (`packages/ax-code/src/mcp/discovery.ts:245-264`); CDP probing is fixed to loopback (`packages/ax-code/src/mcp/discovery.ts:29,70-85,174`). A High security concern remains in the related add flow: required local-template credentials are collected and placed in `environment`, then serialized into either a project or global JSON config (`packages/ax-code/src/cli/cmd/mcp-impl.ts:618-637,681-713`; `packages/ax-code/src/mcp/templates/index.ts:206-222`). Choosing a project config can therefore put GitHub, database, or cloud credentials in a repository file without a plaintext/commit warning.

## Step 3 Discovery Correctness and Failure Semantics

Project recognition short-circuits on HTML/app paths and otherwise combines production and development dependencies (`packages/ax-code/src/mcp/discovery.ts:94-119`). Playwright selection correctly chooses a global binary when present, otherwise `npx`, and makes CDP versus headless arguments exclusive (`packages/ax-code/src/mcp/discovery.ts:155-190`). Aggregate discovery isolates candidate failures and preserves candidate order (`packages/ax-code/src/mcp/discovery.ts:273-305`), while `available` performs the advertised detected-only filter (`packages/ax-code/src/mcp/discovery.ts:319-321`). A Medium behavior bug exists in the consumer: `mcp list --discover` returns at `packages/ax-code/src/cli/cmd/mcp-impl.ts:129-133` when no configured servers exist, before the opt-in discovery block at `packages/ax-code/src/cli/cmd/mcp-impl.ts:234-246`, defeating discovery in the main empty-config onboarding case. Also, GitHub and Postgres are marked detected from credentials alone without proving `npx` is runnable (`packages/ax-code/src/mcp/discovery.ts:203-217`).

## Step 4 Concurrency and Resource Bounds

Candidate checks run concurrently through `Promise.allSettled` (`packages/ax-code/src/mcp/discovery.ts:273-291`). Process probes default to five seconds, the global Playwright check uses three seconds, TCP uses 500 ms, and Exa uses three seconds (`packages/ax-code/src/mcp/discovery.ts:41-55,70-84,170-174,250-260`). Timeout cleanup escalates process termination in `packages/ax-code/src/util/process.ts:121-176,184-190`, and the Exa response body is explicitly cancelled. The Playwright candidate nevertheless performs a full discovery in `check` and repeats it in `resolve` (`packages/ax-code/src/mcp/discovery.ts:229-242`), so a qualifying web project can repeat filesystem checks, command spawns, and the TCP probe. That contradicts the nearby single-probe rationale and introduces avoidable startup latency plus a small check/resolve race.

## Step 5 Configuration Ownership and Composition

The shared timeout is consumed by runtime MCP operations (`packages/ax-code/src/mcp/impl.ts:36-40`) and by configuration documentation (`packages/ax-code/src/config/schema-impl.ts:7-11,40-42`), avoiding divergent defaults. Template conversion matches the strict local and remote schemas: local commands become one string array with optional `environment`, while remotes receive only an HTTP(S) URL (`packages/ax-code/src/mcp/templates/index.ts:194-222`; `packages/ax-code/src/config/schema-impl.ts:44-55,77-94`). Discovery and templates duplicate server names, descriptions, commands, and URLs (`packages/ax-code/src/mcp/discovery.ts:193-267`; `packages/ax-code/src/mcp/templates/index.ts:23-166`), so catalog drift is possible. The Exa template declares `EXA_API_KEY` at `packages/ax-code/src/mcp/templates/index.ts:25-33`, but remote conversion cannot carry it and the CLI merely warns when it is absent (`packages/ax-code/src/cli/cmd/mcp-impl.ts:681-708`); that metadata should either map to supported headers/OAuth or be removed.

## Step 6 Defensive Code and Maintenance Signals

`spawnExitsCleanly` converts spawn, timeout, and exit failures to `false` and makes a best-effort tree cleanup (`packages/ax-code/src/mcp/discovery.ts:47-63`). File access and JSON errors intentionally become a negative project signal (`packages/ax-code/src/mcp/discovery.ts:94-119`), and each candidate failure becomes an undetected result (`packages/ax-code/src/mcp/discovery.ts:277-289`). Because the candidate callback catches every rejection, the later non-fulfilled branch at `packages/ax-code/src/mcp/discovery.ts:293-295` is effectively redundant. Two comments no longer match behavior: the public `discover` comment says only passing servers are returned, although every candidate is pushed with a flag (`packages/ax-code/src/mcp/discovery.ts:269-305`), and the Playwright resolve comment claims one probe despite the preceding check calling the same helper (`packages/ax-code/src/mcp/discovery.ts:229-242`). `packageInstalled` also resolves relative to this module (`packages/ax-code/src/mcp/discovery.ts:18-27`), which can miss a dependency installed only in the user's project.
