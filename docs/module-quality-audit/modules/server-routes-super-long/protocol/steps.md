## Step 2 Boundary and threat analysis

The route accepts network input and changes durable/project-scoped and process-global state. The global server validates the requested project directory before entering `Instance.provide` (`packages/ax-code/src/server/server.ts:258-277`), applies runtime-token or optional basic authentication (`server.ts:166-181`), rejects cross-origin privileged browser requests (`server.ts:183-195`), and rate-limits requests at line 196. Locally, `PUT /` validates the body through `BooleanFeatureState` (`super-long.ts:210-212`), and `/status` validates `model` and the branded `SessionID` query (`super-long.ts:35-38,155-157`). The main assets are `ax-code.json`, written under per-file in-process and cross-process locks in `packages/ax-code/src/server/routes/project-config.ts:138-155`, and the global `AX_CODE_SUPER_LONG*` variables written at `super-long.ts:131-133,248-254`. No credential value is accepted or logged in this module; the meaningful hazards are cross-directory state bleed, a control response disagreeing with runtime behavior, and partial persistence/reconciliation.

## Step 3 Correctness and state transitions

Model parsing preserves the provider prefix by splitting only the first `/` (`super-long.ts:44-49`), which is important because `SuperLongPolicy.state` forwards both model and provider to `supportsLongAgent` (`packages/ax-code/src/session/super-long-policy.ts:161-175`); the gateway regression is directly covered at `packages/ax-code/test/server/super-long.test.ts:141-159`. `GET /` reads project config, derives state without env overrides, gates it on autonomous mode, clears the session override, aligns the base env, and records the scoped value (`super-long.ts:111-134`). `PUT /` refuses enablement when autonomous is off (`super-long.ts:212-223`), persists before changing runtime flags (`super-long.ts:224-248`), and preserves object-form duration/pacing settings when toggling `enabled` (`super-long.ts:233-241`). The persistence helper only mutates env/scoped state after a successful locked write (`project-config.ts:52-63`), so a disk failure does not falsely activate the feature.

One Medium defect exists in the autonomous gate. `autonomousEnabled` reads the process-global `AX_CODE_AUTONOMOUS` before the current project's config (`super-long.ts:51-59`) even though `ScopedFlag` documents that such env values become last-writer-wins across directories (`packages/ax-code/src/flag/scoped.ts:3-18`). If project B writes autonomous false after project A recorded true, a `/super-long` request for A returns false despite A's config; the config loader explicitly distinguishes managed env mirrors via `ScopedFlag.isManaged` at `packages/ax-code/src/config/config-impl.ts:721-738`, but this helper does not. A config value of false still vetoes env true, so the defect is cross-project false disablement rather than an unsafe enablement.

## Step 4 Performance and concurrency

Each `GET /` performs one small config-file read (`project-config.ts:132-135`), while `/status` adds one read of the durable runtime JSON when `sessionID` is present (`super-long.ts:175-179`; `packages/ax-code/src/session/super-long-runtime.ts:84-87`). There is no list traversal, database fan-out, or request-sized allocation in the handlers. `PUT /` serializes writers with `Lock.write` plus `FileLock.acquire` and re-reads inside the critical section (`project-config.ts:138-154`), preventing lost updates between concurrent processes. Status lookup is deliberately read-only and does not acquire the write lock or start a run clock (`super-long-runtime.ts:79-87`). Its `.catch(() => undefined)` at `super-long.ts:177-179` converts store failures to null timing; non-ENOENT read failures and malformed top-level stores are logged before propagation at `super-long-runtime.ts:145-155`, so this is an availability tradeoff rather than silent I/O suppression. The route's expected polling cost is bounded by two local JSON reads.

## Step 5 Architecture and ownership

Policy ownership is mostly sound: legacy boolean/object config normalization lives in `SuperLongPolicy.fromConfig` (`super-long-policy.ts:21-34`), runtime precedence lives in `runtimeState` (`super-long-policy.ts:177-207`), and the 72-hour ceiling is enforced by `duration` (`super-long-policy.ts:209-228`). The route delegates to those functions at `super-long.ts:69-89` instead of duplicating capability or duration logic. Session ownership is checked before status exposes timing: `super-long.ts:175-178` calls `requireCurrentProjectSession`, whose compatibility guard returns HTTP 409 for another directory (`packages/ax-code/src/server/routes/session-lookup.ts:10-21`). Runtime consumers actually prefer `ScopedFlag.superLong()` in deadline enforcement (`packages/ax-code/src/session/prompt-super-long.ts:28-37`) and LLM setup (`packages/ax-code/src/session/llm-impl.ts:199-214`), which makes scoped reconciliation a contract, not an incidental cache.

The route and `packages/ax-code/src/server/routes/autonomous.ts:15-16` duplicate the two env-variable names whose canonical equivalents are private constants at `super-long-policy.ts:6-8`. This is a Low maintainability concern: a rename has three string owners and no type-level linkage. Exporting the names or centralizing the state transition behind the policy/flag layer would remove that drift risk.

## Step 8 Finding register and disposition

No pre-existing finding file was present under `docs/module-quality-audit/modules/server-routes-super-long/findings/`; `MODULE-AUDIT.md:60-64` likewise says none accepted. This review records three actionable items in the protocol:

1. **High — `/status` performs incomplete reconciliation.** It clears the override and writes `AX_CODE_SUPER_LONG` at `super-long.ts:167-171` but omits the `ScopedFlag.recordCurrent` call used by `GET /` at lines 131-133. After an external config edit, `/status` can report the new `enabled` value while runtime readers continue using the stale scoped value, because scoped state has first precedence at `super-long-policy.ts:183-201` and is consumed at `prompt-super-long.ts:28-37`. Fix by recording `enabled` in the current scope during status reconciliation, then add a regression test that edits config between requests.
2. **Medium — autonomous gating is process-global across projects.** `super-long.ts:51-59` ignores the managed/scoped distinction established by `scoped.ts:25-29,63-75`; a false env mirror from another directory disables Super-Long in the current directory. Resolve pristine env overrides separately from managed mirrors, consistent with `config-impl.ts:721-738`, and test two live project directories.
3. **Low — persistence failure is absent from OpenAPI and uses a nonstandard body.** The 500 return at `super-long.ts:244` is not declared at lines 198-208 and does not use `AppErrorEnvelope` (`error.ts:10-24`). Add the 500 response schema or route the failure through the standard error helper.

None is Critical, so the requested Critical-only `reverify.md` is not created. The High item requires correction and regression coverage before treating `/status` as a reliable control-plane reconciliation endpoint.
