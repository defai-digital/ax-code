Verifier lane: `ax-code-glm`

## Step 1 Scope and published surface

The `pkg-opentui-solid` package publishes separate Node and Bun roots plus preload, transform, plugin-support, component, and JSX-runtime subpaths at `packages/opentui-solid/package.json:10-60`. The root declaration exposes `render`, `testRender`, the reconciler, elements, scrollback, slot plugin, and JSX types at `packages/opentui-solid/index.d.ts:1-12`; the built runtime exports the corresponding implementation set at `packages/opentui-solid/index.js:1578-1627`. `components.js:77-108` supplies the intrinsic catalogue and its extension API, while `jsx-runtime.js:2-30` removes JSX keys, distinguishes function components from intrinsic strings, and implements `Fragment`. I also followed the package-owned Babel transform in `packages/opentui-solid/scripts/solid-transform.js:30-64` because the plugin entrypoints call it directly.

## Step 2 Runtime and trust boundaries

The significant boundary is executable source entering Bun's loader hooks. `packages/opentui-solid/scripts/solid-plugin.js:35-70` restricts source transforms to local JS/TS/JSX/TSX paths outside `node_modules`, reads those paths with `Bun.file`, then feeds their content and filename to Babel. Optional runtime rewriting enters through `runtime-plugin-support-configure.js:17-34`; compatibility checks reject a later installation that lacks a requested specifier or changes core/rewrite identity. Installation mutates process-global state with `Symbol.for` at `runtime-plugin-support-configure.js:8,36-64` and registers a Bun plugin, so order is intentionally observable. This package does not itself fetch network content, spawn processes, or read credentials. The preload is side-effectful by design (`scripts/preload.js:1-2`), whereas the Node preload rejects explicitly at `scripts/preload.node.js:1`.

## Step 3 Correctness and lifecycle behavior

Renderer teardown is guarded against destroy-during-mount: `packages/opentui-solid/index.js:1511-1555` temporarily defers `renderer.destroy`, restores the original method in `finally`, and runs the Solid disposer once. Event hooks pair every subscription with cleanup at `index.js:111-188`, and timeline cleanup pauses and unregisters at lines 189-201. Scrollback construction tears down the Solid root and recursively destroys its render root on failure at `index.js:1291-1322`. A concrete package defect exists in the unsupported-runtime paths: `package.json:23-27,34-44` directs Node to three `.node.js` files, but `runtime-plugin-support-configure.node.js:1-8`, `runtime-plugin-support.node.js:1-8`, and `solid-plugin.node.js:1-16` each redeclare `const errorMessage` after concatenated copies. `node --check` rejects all three before their intended descriptive Bun-only error can execute.

## Step 4 Performance and resource bounds

The Node renderer bounds its decode, color, and text-attribute caches to 500, 100, and 50 keys respectively, clearing each map at its limit (`packages/opentui-solid/index.js:211-251`). The Bun bundle uses the direct core/entity helpers instead (`packages/opentui-solid/index.bun.js:216-237`), a runtime-specific difference rather than unbounded growth. Array reconciliation uses a map only after prefix/suffix and swap fast paths fail (`index.js:371-425`). Automatic scrollback height is capped at four layout passes by `MAX_AUTO_HEIGHT_PASSES` and the loop at `index.js:1185-1187,1260-1269`. Plugin installation is idempotent through global state (`scripts/solid-plugin.js:3-28`), and runtime-plugin installation returns `false` on a compatible repeat at `runtime-plugin-support-configure.js:41-45`. No unbounded retry, timer, or retained per-render listener was found in the reviewed paths.

## Step 5 Design and ownership

The package owns the Solid-to-OpenTUI adapter while renderable primitives remain in `@ax-code/opentui-core`, as the imports and catalogue show at `packages/opentui-solid/components.js:2-17,77-104`. The stable transform boundary documented in `packages/opentui-solid/README.md:5-11` matches the `./transform` export at `package.json:29-33`; Bun loader concerns stay in `solid-plugin.js`, and source transformation stays in `solid-transform.js`. Platform routing is explicit in the export map instead of runtime sniffing. The main maintainability cost is generated-surface duplication: the catalogue appears in both `components.js:19-108` and `index.js:8-99`, while the root Node and Bun bundles carry nearly the same renderer. The malformed Node stubs demonstrate the drift risk; the valid sibling pattern in `packages/opentui-core/runtime-plugin-support-configure.node.js:1-15` contains one declaration and one terminating error.

## Step 6 Error handling and hygiene

The recorded silent-error site is `LayoutSlotRenderable.freeYogaNode`: it marks the Yoga node freed before calling `free`, then suppresses any exception at `packages/opentui-solid/index.js:975-983` and the equivalent Bun site at `index.bun.js:952-960`. Because the method is cleanup and the guard prevents a double-free retry, this is not a Critical path, but the empty catch can conceal a failed native-resource release; the existing Low/deferred finding is justified. By contrast, JSON serialization failure in the text-attribute cache has an explicit fallback and comment at `index.js:236-245`. Plugin slot rendering reports both synchronous renderer failures and error-boundary failures through the registry at `index.js:1425-1453`, and scrollback uses `finally` while measuring layout at lines 1246-1258. No TODO or disabled security branch was found in the candidate JavaScript.

## Step 7 Type contracts and test coverage

The root declaration's async signatures (`packages/opentui-solid/index.d.ts:4-5`) match `render` and `testRender` at `index.js:1557-1576`, and component extension declarations match the mutable catalogue implementation (`components.d.ts:1-2`; `components.js:99-105`). Type precision is weaker for two documented built-ins: runtime catalogue entries `diff` and `line_number` exist at `components.js:86-88` and are documented at `README.md:147-151`, but `jsx-runtime.d.ts:29-49` gives neither an explicit intrinsic property nor specialized props for them. Focused tests cover the stable transform export at `packages/ax-code/test/script/esbuild-solid-plugin.test.ts:16-39` and only the existence/routing of selected package files at `opentui-package-integrity.test.ts:30-71`. That integrity test does not parse the three Node plugin stubs, and the audit-listed FFI and spinner tests exercise sibling packages rather than renderer lifecycle, slots, JSX key normalization, or this package's Node rejection behavior.

## Step 8 Findings and severity decision

The existing ledger contains one Low, deferred silent-error finding at `docs/module-quality-audit/modules/pkg-opentui-solid/findings/AUDIT-pkg-opentui-solid-empty-catch.md:3-20`, consistent with the two bundle copies of the same Yoga cleanup source. This review additionally identifies a Medium packaging-quality defect: the three Node conditional-export targets cited in Step 3 are syntactically invalid because duplicated stub bodies were concatenated. Supported Bun behavior is not affected, and Node use of those entrypoints is deliberately unsupported, but consumers receive a parser failure rather than the package's promised actionable error and syntax-aware tooling cannot load the files. The JSX intrinsic typing gap from Step 7 is Low. No finding is Critical, so the conditional `protocol/reverify.md` artifact is not required.

## Step 9 Verification and exit

The nine review steps for `pkg-opentui-solid` are complete under reviewer `codex-sol`; verifier metadata is assigned to `ax-code-glm`.
