# Review Protocol: tool-network

## Step 1 Surface and Boundary Map

The `tool-network` unit has seven thin browser tool adapters at `packages/ax-code/src/tool/browser/action.ts:7-56`, `capture.ts:6-45`, `console.ts:6-35`, `evaluate.ts:6-31`, `network.ts:6-50`, `open.ts:7-48`, and `snapshot.ts:6-28`. They converge on the process-level `BrowserRuntime` at `packages/ax-code/src/tool/browser/runtime.ts:195-677`. The non-browser side consists of the shared Exa transport and decoder (`packages/ax-code/src/tool/exa-fetch.ts:25-149`), the URL fetch/format pipeline (`packages/ax-code/src/tool/webfetch.ts:23-286`), and the Exa search request builder (`packages/ax-code/src/tool/websearch.ts:8-82`). Registration confirms web fetch/search are unconditional while browser tools are feature-gated at `packages/ax-code/src/tool/registry.ts:248-250` and `276-289`.

## Step 2 Inputs and Failure Boundaries

Untrusted inputs include URLs, redirect locations, search queries, JavaScript function strings, DOM-derived UIDs, upload paths, response headers/bodies, and page-produced console/network data. `WebFetchTool` parses the initial URL and limits it to HTTP(S) at `packages/ax-code/src/tool/webfetch.ts:34-42`; `BrowserOpenTool` delegates only protocol validation to `BrowserPermission.validateUrl` at `packages/ax-code/src/tool/browser/open.ts:20-33` and `packages/ax-code/src/visual/permission.ts:64-77`. The broadest authorities are page-context execution at `packages/ax-code/src/tool/browser/runtime.ts:595-616` and local-file upload through `setInputFiles` at `runtime.ts:497-504`. Remote response volume and redirect behavior are separate availability and SSRF boundaries in `packages/ax-code/src/tool/exa-fetch.ts:53-104` and `packages/ax-code/src/tool/webfetch.ts:93-196`.

## Step 3 Behavioral Correctness

The web-fetch flow revalidates every manual redirect, requests permission again on an origin change, streams into a bounded buffer, and dispatches image/text/HTML/Markdown results at `packages/ax-code/src/tool/webfetch.ts:93-219` and `230-275`. Exa parsing deliberately keeps the last content-bearing SSE event (`packages/ax-code/src/tool/exa-fetch.ts:113-136`). Browser action dispatch validates required action-specific values and invalidates UIDs after explicit navigation (`packages/ax-code/src/tool/browser/runtime.ts:384-508`). Several advertised contracts do not match execution: `verbose` is passed at `packages/ax-code/src/tool/browser/snapshot.ts:9-17` but never used by `runtime.ts:342-381`; console and network buffers survive navigation despite the descriptions claiming “since the last page navigation” (`runtime.ts:443-475`, `559-593`); and `browser-open.txt:2` promises the resulting URL while `runtime.ts:323-339` stores and returns the requested URL even after redirects. `webfetch.txt:10` also promises HTTP-to-HTTPS upgrade, which `webfetch.ts:34-49` does not perform.

## Step 4 Security and Policy Enforcement

`WebFetchTool` and `WebSearchTool` enforce the session isolation network bit at `packages/ax-code/src/tool/webfetch.ts:44` and `packages/ax-code/src/tool/websearch.ts:43`, backed by `packages/ax-code/src/isolation/index.ts:223-229`. No browser wrapper performs that check (`packages/ax-code/src/tool/browser/open.ts:19-36`; `action.ts:30-46`), so the experimental browser can create network traffic under a network-disabled tool context. Permission is checked for explicit open/navigate URLs (`open.ts:20-36`; `action.ts:31-46`), but Playwright follows `goto` redirects and click-driven navigations without validating or asking for the destination (`runtime.ts:323`, `395-403`, `466-470`). Upload accepts arbitrary filesystem paths and sends them to the page without file-read/isolation authorization (`action.ts:28`, `runtime.ts:497-504`). Finally, one static singleton and one `latestPageID` serve every caller (`runtime.ts:195-226`, `244-253`), while every wrapper selects `"latest"` (for example `snapshot.ts:15-17` and `network.ts:32-37`), creating cross-session observation and control risk. These security-significant gaps are absent from the current single-item findings ledger and prevent a clean security sign-off.

## Step 5 Resource and Performance Resilience

The good bounds are explicit: console and network history use 500-entry ring buffers (`packages/ax-code/src/tool/browser/runtime.ts:114-115`, `256-274`), Exa success bodies stop at 1 MiB (`packages/ax-code/src/tool/exa-fetch.ts:7`, `82-103`), and web fetch checks both Content-Length and streamed bytes against 5 MiB (`packages/ax-code/src/tool/webfetch.ts:162-196`). Abort timers are cleared and bodies are cancelled in `exa-fetch.ts:137-147` and `webfetch.ts:276-283`. Remaining pressure points are the unbounded `response.text()` on Exa error responses (`exa-fetch.ts:76-80`), an all-DOM recursive snapshot with uncapped text construction (`runtime.ts:130-188`, `350-375`), and a context leak if `newContext`/`newPage` succeeds but `goto` or `title` fails before the page is registered (`runtime.ts:294-335`). Normal runtime shutdown closes contexts and clears registries at `runtime.ts:619-643`, but no public browser-close tool associates that cleanup with a session.

## Step 6 Design and Ownership

The wrapper/runtime split is cohesive: Zod schemas and tool result shaping remain in the small adapter files, while Playwright lifecycle, page state, capture, evaluation, and buffers live in `packages/ax-code/src/tool/browser/runtime.ts:195-677`. Web fetch correctly delegates DNS pinning and public-address validation to `Ssrf` (`packages/ax-code/src/tool/webfetch.ts:17-21`), and browser host pattern construction is centralized through `BrowserPermission.permissionPatterns` (`packages/ax-code/src/visual/permission.ts:80-86`). The ownership flaw is scope: the runtime comment says the browser persists for a session (`runtime.ts:4-7`), but the implementation has no session key and tools never pass `ctx.sessionID`. Also, the supposedly stable `BrowserSnapshot` shape at `runtime.ts:29-33` cannot represent the computed styles or bounding boxes promised by `packages/ax-code/src/tool/browser/snapshot.ts:9-12`, so the public schema itself blocks the verbose contract.

## Step 7 Hygiene and Error Semantics

The registered Low item points to the empty catch around `reader.releaseLock()` at `packages/ax-code/src/tool/webfetch.ts:276-283`. In context this is best-effort finalization followed by body cancellation, so swallowing that cleanup-only exception does not conceal the primary fetch result, though a local rationale would make the intent match the commented catches at `packages/ax-code/src/tool/browser/runtime.ts:619-639` and `650-667`. There are no TODO/FIXME markers in the candidate sources. The no-argument evaluation path correctly leaves code inside the browser context (`runtime.ts:615-616`), but the multi-argument path constructs functions in Node and passes Playwright `Locator` objects through `page.evaluate` (`runtime.ts:598-612`); that branch lacks proof that the locators serialize as element handles and should be treated as an unverified correctness path rather than justified `any` usage.

## Step 8 Focused Test Assessment

The runtime suite exercises action dispatch, pagination, UID escaping, capture, evaluation with zero or one UID, and cleanup (`packages/ax-code/test/tool/browser/runtime.test.ts:128-629`). Adapter tests cover origin-scoped browser-open permission and capture attachments (`packages/ax-code/test/tool/browser-open.test.ts:10-44`; `browser-capture.test.ts:10-42`), while web fetch tests cover formatting, permission scope, redirect revalidation, cross-origin permission, and body cancellation (`packages/ax-code/test/tool/webfetch.test.ts:35-344`). Exa decoding and search-query permission have focused assertions at `packages/ax-code/test/tool/exa-fetch.test.ts:4-34` and `packages/ax-code/test/tool/network-search-permission.test.ts:20-46`. The seven selected files passed 61 tests. Missing regressions include multi-session browser ownership, network-disabled browser calls, redirect/click destination approval, upload path authorization, failed-open cleanup, verbose snapshots, navigation buffer reset, multi-UID evaluation, and direct wrappers for console/evaluate/network/snapshot.
