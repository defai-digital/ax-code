## Step 2 Native trust and I/O boundaries

The declaration is synchronous but crosses several native I/O boundaries. `AdvisoryLock` accepts a caller-provided path (`packages/ax-code-index-core/index.d.ts:8`) and its implementation creates parent directories before opening the lock file (`crates/ax-code-index/src/lock.rs:23-50`). `IndexStore` likewise accepts a database path (`packages/ax-code-index-core/index.d.ts:55`), opens SQLite, applies PRAGMAs, and creates tables (`crates/ax-code-index/src/store.rs:24-39`). `hashFileSha256` exposes arbitrary file reads at `packages/ax-code-index-core/index.d.ts:109`; the implementation streams the file in 8 KiB chunks (`crates/ax-code-index/src/hasher.rs:13-26`). Database values use SQLite parameters, for example edge filters at `crates/ax-code-index/src/edge.rs:91-136`, so caller strings do not become raw SQL. JSON write inputs are deserialized before mutation (`crates/ax-code-index/src/node.rs:61-68`, `crates/ax-code-index/src/file.rs:203-208`). No network access, process spawning, environment-secret lookup, or credential logging appears in the reviewed binding and implementation paths.

## Step 3 Store lifecycle and mutation correctness

The close contract documented in `packages/ax-code-index-core/index.d.ts:56-69` matches the implementation: the connection is stored as `Mutex<Option<Connection>>`, taken once, and subsequent access returns “index store is closed” (`crates/ax-code-index/src/store.rs:54-72,76-105`). Multi-table project deletion is transactional (`crates/ax-code-index/src/cursor.rs:59-82`), and file ingestion parses all three payloads before opening a transaction and commits only after delete/insert/upsert work succeeds (`crates/ax-code-index/src/file.rs:193-211,237-276`). One non-Critical robustness gap remains in the public raw-JSON API: `ingestFile` declares separate `projectId`/`filePath` arguments and payload strings (`packages/ax-code-index-core/index.d.ts:45-46`), while the Rust inserts each payload's own `project_id` and `file` fields without checking that they equal those arguments (`crates/ax-code-index/src/file.rs:243-272`). The in-repo adapter serializes coherent builder-owned rows at `packages/ax-code/src/code-intelligence/native-store.ts:231-240`, so normal product use is controlled, but direct consumers can create logically split data.

## Step 4 Concurrency and performance behavior

SQLite access is serialized through one mutex (`crates/ax-code-index/src/store.rs:18-20,77-105`) and configured for WAL, a 5-second busy timeout, and a 256 MiB mmap (`crates/ax-code-index/src/schema.rs:74-81`). Bulk node and edge inserts reuse prepared statements inside transactions (`crates/ax-code-index/src/node.rs:70-97`, `crates/ax-code-index/src/edge.rs:64-88`), and file pruning narrows by escaped scope prefix before deleting orphan rows transactionally (`crates/ax-code-index/src/file.rs:124-157,162-189`). The `IntervalTree` complexity claim deserves correction: both the generated declaration (`packages/ax-code-index-core/index.d.ts:72-78`) and Rust comment (`crates/ax-code-index/src/interval_tree.rs:41-45`) say O(log n), but after `partition_point` each lookup scans `intervals[..search_idx]` (`crates/ax-code-index/src/interval_tree.rs:108-130,151-166`), making worst-case lookup O(n). Also, `AdvisoryLock.acquire` sleeps synchronously in 500 ms slices (`crates/ax-code-index/src/lock.rs:102-126`); the shipping TypeScript lock path instead uses the non-blocking `tryAcquire` loop (`packages/ax-code/src/code-intelligence/lockfile.ts:137-148,178-190`).

## Step 5 Ownership and binding design

Publication metadata includes the JavaScript shim, declaration, and platform `.node` files (`packages/ax-code-index-core/package.json:7-20`) for five declared targets. Runtime loading is intentionally centralized: `packages/ax-code/src/native/addon.ts:23-30` uses the declaration as a type-only binding, and `NativeAddon.index()` loads it behind the native-index flag at `packages/ax-code/src/native/addon.ts:47-64,78-80`. The architectural split is coherent, though raw JSON strings in `IndexStore` deliberately leave row-shape validation to Rust rather than TypeScript.

## Step 6 API hygiene and failure semantics

The declaration has no implementation bodies, TODO/FIXME markers, catches, or dead branches; generated lint suppression is explicit at `packages/ax-code-index-core/index.d.ts:1-2`. Nullable query results are represented consistently (`getCursor`, `getFile`, and `getNode` at `packages/ax-code-index-core/index.d.ts:26,40,48`), optional edge filters accept `undefined | null` (`index.d.ts:33-34`), and release/close idempotence is implemented at `crates/ax-code-index/src/lock.rs:129-177` and `crates/ax-code-index/src/store.rs:54-72`. A failure-semantics caveat is hidden by the opaque `optsJson: string` signatures at `packages/ax-code-index-core/index.d.ts:49-50`: malformed option JSON silently becomes an unfiltered options object in `crates/ax-code-index/src/node.rs:117-127,161-172`, whereas malformed insert and ingest JSON returns an error. In-repo calls always pass `JSON.stringify(opts ?? {})` (`packages/ax-code/src/code-intelligence/native-store.ts:104-123`), but direct callers would benefit from consistent rejection or a documented fallback.
