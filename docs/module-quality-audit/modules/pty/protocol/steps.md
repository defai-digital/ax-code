## Step 2 Threat and failure model

This unit is tagged `security, resource` in MODULE-AUDIT.md and the code justifies it. The four security-relevant boundaries I traced: (a) **cwd escape** — `resolveCwd` at index.ts:379-398 calls `fs.realpath` on both `Instance.directory` and the requested cwd, then `Filesystem.contains(projectRoot, targetCwd)`; the symlink-escape test at `packages/ax-code/test/pty/pty-session.test.ts:195` confirms a link to an outside dir is rejected with `PtyInvalidCwd`. (b) **env injection** — `FORBIDDEN_USER_ENV_KEYS` at index.ts:26-41 strips `LD_PRELOAD`, `DYLD_INSERT_LIBRARIES`, `NODE_OPTIONS`, `PATH`, `SHELL`, etc.; `sanitizeUserEnv` at index.ts:131-142 additionally runs `Env.sanitize` first to drop credential-bearing names, and the keys are matched by `key.toUpperCase()` so `node_options` cannot slip through case-folded. (c) **terminal size DoS** — `TerminalSize` at index.ts:250-253 uses `JsonNumber(z.number().int().min(1).max(1000))` for rows/cols, fixing the issue referenced as #244 that let negative/NaN/huge values reach `proc.resize`. (d) **process/resource** — `teardown` at index.ts:269-291 kills the process and closes every subscriber; `Instance.state` registers an async disposer at index.ts:298-303 that iterates and tears down every live session on instance shutdown.

## Step 3 Correctness of public surfaces

I read each exported function against its caller contract. `resize(id, cols, rows)` at index.ts:316-323 validates via `TerminalSize.parse` **before** touching `session.process.resize`, and guards on `status === "running"` so a resize on an exited process is a no-op rather than a native throw. `write(id, data)` at index.ts:325-331 applies the same status guard. `connect(id, ws, cursor?)` at index.ts:333-377 closes the socket if the session is missing, replays buffered output through `replayBufferedOutput`, and on a `trySendBuffered`/`trySend` failure calls `cleanup()` then `ws.close()` so a half-broken socket never lingers in the subscriber map. `replayBufferedOutput` at index.ts:83-109 handles all four branches correctly: empty buffer, `actualFrom >= end`, offset past buffer length, and the normal slice; when `from < start` it returns a `gap: { requested, available }` meta so the client knows data was lost — this branch is covered by the test at pty-session.test.ts:77. `remove(id)` at index.ts:520-532 is idempotent (returns early if absent) and only publishes `Exited` when the process hadn't already exited, avoiding duplicate exit events.

## Step 4 Performance and resource behavior

The output buffer is hard-bounded: `BUFFER_LIMIT = 1024 * 1024 * 2` at index.ts:22 and the trim logic at index.ts:486-489 slices off the excess and advances `bufferCursor` by the same amount, so memory is O(2 MiB) per session regardless of process output volume — this is sound. Live fan-out in the `onData` handler at index.ts:460-491 iterates `session.subscribers.entries()` and lazily evicts any socket whose `readyState !== 1`, so dead WebSocket connections do not accumulate. Large replays are chunked at `BUFFER_CHUNK = 64 * 1024` via `trySendBuffered` at index.ts:120-129 to avoid hitting WebSocket frame limits. One concern worth noting (not a finding because it is bounded): the `onData` callback runs `session.buffer += chunk` followed by a potential `session.buffer.slice(excess)` on every overflow, which is a single 2 MiB copy per overflow event — acceptable given the cap. The native addon is loaded via `lazy(async () => loadNodePtySpawn())` at index.ts:211-213, so importing `Pty` does not pull the native binary until a terminal is actually created.

## Step 5 Design and ownership

Ownership is unambiguous: `Instance.state` at index.ts:293-304 owns the `sessions: Map<PtyID, Active>` and registers the teardown disposer, so sessions cannot outlive their parent instance. The `Active` shape at index.ts:52-60 groups everything that must be torn down together (`process`, `subscribers`, `dispose` array of `{ dispose: () => void }`), and `teardown` consumes exactly those fields. The dual-key subscriber logic at index.ts:344-347 + 469-477 is the one genuinely subtle piece — the comment at index.ts:469-473 explains why the recycled-socket guard `key !== ws && ws.data !== key` is correct: when `ws.data` was undefined and we fell back to using `ws` itself as the key, the guard would otherwise always be true and drop a live subscriber on its first chunk. The lazy-loaded node-pty with bundled-fallback (`loadBundledNodePty` at index.ts:185-195 trying `ax-code-${platform}-${arch}` then `ax-code-node-tui`) is a reasonable choice for a hybrid source/bundled distribution, and the `suppressNodePtyDebugFallbackNoise` wrappers at index.ts:155-179 keep the spurious `build/Debug/pty.node` stderr out of logs without hiding anything else.
