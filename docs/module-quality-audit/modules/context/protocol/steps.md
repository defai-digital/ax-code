## Step 1 Surface and dependency map

The public generation path is `Context.init`: it chooses `AGENTS.md`, preserves an existing file unless forced, analyzes the checkout, renders content, and optionally writes it (`packages/ax-code/src/context/index.ts:36-81`). Analysis assembles language, stack, layout, scripts, package manager, runtime, and complexity data (`packages/ax-code/src/context/analyzer.ts:92-119`), while `generate` turns that record into ordered Markdown sections (`packages/ax-code/src/context/generator.ts:26-63`). The separate `LongAgentContextPacker.pack` API builds four priority tiers and `render` concatenates admitted entries (`packages/ax-code/src/context/long-agent-packer.ts:59-147`). Production callers are the `init` CLI (`packages/ax-code/src/cli/cmd/init.ts:53-76`) and the super-long session paths (`packages/ax-code/src/session/llm-impl.ts:266-283`, `packages/ax-code/src/session/processor-impl.ts:989-1019`).

## Step 2 Trust and failure boundaries

The analyzer reads checkout-controlled `package.json` data and filesystem structure; malformed, unreadable, and missing manifests all collapse to `null` because `readPackageJson` catches every read/parse error (`packages/ax-code/src/context/analyzer.ts:148-157`). Manifest names, descriptions, scripts, paths, and optional external rules become Markdown, but this module does not execute those script strings (`packages/ax-code/src/context/generator.ts:90-106`, `packages/ax-code/src/context/generator.ts:148-154`, `packages/ax-code/src/context/generator.ts:190-226`). The only product write is the caller-selected root plus `AGENTS.md`, with non-ENOENT read errors propagated and `dryRun` suppressing the write (`packages/ax-code/src/context/index.ts:36-74`). Long-agent task and touched-file text enters provider system context at `packages/ax-code/src/session/llm-impl.ts:267-279`; logs retain only counts and a size summary at lines 280-283, not packed content.

## Step 3 Behavioral correctness

Detection precedence is deterministic, package values are runtime-decoded, source scanning is capped, and `Context.read` distinguishes absence from other I/O errors (`packages/ax-code/src/context/analyzer.ts:122-146`, `packages/ax-code/src/context/analyzer.ts:177-235`, `packages/ax-code/src/context/index.ts:84-91`). One concrete contract defect remains in the packer: admission charges only `entry.content.length` (`packages/ax-code/src/context/long-agent-packer.ts:60-69`), but `totalTokens` and `render` include two newline characters between entries (`packages/ax-code/src/context/long-agent-packer.ts:131-146`). A direct probe with budget `1`, task `"aa"`, and agents text `"bb"` admitted both entries and returned `totalTokens: 2`. Production task extraction is capped at 500 characters and touched files at 20 (`packages/ax-code/src/session/llm-impl.ts:1015-1046`), limiting the main prompt-path impact, but the exported generic packer accepts unbounded arrays.

## Step 4 Resource behavior

Complexity analysis bounds work to 5,000 source files and reads in batches of 50, using concurrent reads within each batch (`packages/ax-code/src/context/analyzer.ts:396-433`); dependency counting is linear in manifest dependency keys (`packages/ax-code/src/context/analyzer.ts:443-449`). Generation is linear in the small `ProjectInfo` collections and caps displayed stack, key-file, custom-script, and tip lists (`packages/ax-code/src/context/generator.ts:98-100`, `packages/ax-code/src/context/generator.ts:148-154`, `packages/ax-code/src/context/generator.ts:179-185`, `packages/ax-code/src/context/generator.ts:265-276`). Packing is linear in candidates, though computing `totalTokens` joins all admitted content and the later `render` call joins it again (`packages/ax-code/src/context/long-agent-packer.ts:131-146`); configured production budgets are 8,000, 64,000, or 128,000 tokens (`packages/ax-code/src/provider/agent-optimization-profile.ts:51-74`), so this duplicate allocation is bounded and not presently a hot-path severity finding.

## Step 5 Cohesion and API design

Responsibilities are cleanly separated: filesystem inference lives in `analyzer.ts`, pure Markdown assembly in `generator.ts`, lifecycle/I/O in `index.ts`, and session-prompt prioritization in `long-agent-packer.ts`. `Context.refresh` reuses `init` with `force: true` rather than duplicating behavior (`packages/ax-code/src/context/index.ts:94-96`), and the session layer supplies model-derived budgets rather than making the packer depend on provider policy (`packages/ax-code/src/session/llm-impl.ts:266-275`). Two API rough edges are visible: `generate` publicly accepts `Partial<GeneratorConfig>` while `GeneratorConfig` itself is not exported (`packages/ax-code/src/context/generator.ts:11-26`), and `CodeConventions.packageManager` duplicates top-level `ProjectInfo.packageManager` without any assignment or consumer (`packages/ax-code/src/context/analyzer.ts:29-37`, `packages/ax-code/src/context/analyzer.ts:49-75`).

## Step 6 Maintenance and latent branches

There are no TODO, FIXME, HACK, suppression, or `any` hits in the four module files. The catches in `exists` and `pathExists` intentionally turn probing failures into absence (`packages/ax-code/src/context/analyzer.ts:160-175`), while the broader `readPackageJson` catch also hides malformed JSON and permission errors despite its comment discussing ENOENT/TOCTOU (`packages/ax-code/src/context/analyzer.ts:148-157`); that loss of diagnostic truth is a quality concern. `CodeConventions.strict` is read by the generator (`packages/ax-code/src/context/generator.ts:209-211`) but is never populated by `detectConventions` (`packages/ax-code/src/context/analyzer.ts:289-314`), so the normal `Context.init` path cannot emit its strict-mode rule. The packer is live code, used for both provider prompt injection and optimization traces (`packages/ax-code/src/session/llm-impl.ts:269-283`, `packages/ax-code/src/session/processor-impl.ts:993-1019`).

## Step 8 Finding decisions

No Critical evidence exists, so an independent `reverify.md` is not required.
