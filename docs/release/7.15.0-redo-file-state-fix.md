# Redo file-state correction for 7.15.0

Official `v7.15.0` (`32660f757`) includes the earlier session transport, Windows console, and snapshot enumeration fixes, but does not include the partial/full Redo correction from `0857299ad`. This branch ports that correction and its filesystem regression test onto 7.15.0.

## Problem and correction

After undoing two turns and redoing only the first, messages could become visible while files affected exclusively by that first turn remained undone. The new revert plan retains the new boundary's patches and restores the previously affected remaining paths from the snapshot saved before the first undo. Preview uses the same plan without modifying files.

Full redo previously restored snapshot contents through a whole-tree checkout, leaving files that should be deleted on disk. It now restores the affected paths through `Snapshot.revert`, which handles absence in the target snapshot. Unrelated manual edits and newly created files are preserved. If clearing the revert metadata fails, the affected files roll back to their state before redo.

## Regression coverage

`test/session/redo-files.test.ts` exercises real temporary Git repositories and isolated SQLite session data. It covers two-level undo, partial redo, full redo both directly and after partial redo, file addition/modification/deletion, Chinese filenames with spaces, CRLF preservation, message boundaries and cleanup, non-mutating preview, unrelated manual edits, and injected metadata failure with retry.

Related suites cover descendant rollback, busy-session and worktree protections, compact after revert, Windows snapshot paths, and TUI error handling. The UI checks do not constitute a mouse/keyboard end-to-end test.

Run from `packages/ax-code`:

```powershell
$env:AX_TEST_FILES='test/session/redo-files.test.ts,test/session/descendant-rollback.test.ts,test/session/rollback.test.ts,test/session/revert-compact.test.ts,test/cli/tui/session-revert.test.ts,test/cli/tui/h-session-undo-redo-revert-error.test.ts,test/snapshot/windows-paths.test.ts'
node ../../node_modules/vitest/vitest.mjs run --retry=0
```
