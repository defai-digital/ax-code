# Issue #451 本地修复与测试报告

## 结论

基于 `v7.18.1`（`a3e1de36ecc8a44dbb59590bec5309dc8cb0cc65`）修复普通非 Git 目录无法撤回文件修改的问题。修改位于本地分支 `fix/non-git-revert-451`，使用独立工作树，避免混入原工作区已有改动。

## 根因与修改

原来的 `Snapshot.enabled()` 在 `project.vcs !== "git"` 时直接禁用快照。会话没有生成文件补丁，但 Revert 仍设置消息撤回状态，导致消息消失、文件保留。

本次移除该目录类型限制。普通目录现在复用 ax-code 数据目录内、按项目 ID 隔离的内部 Git 快照仓库，支持现有快照、预览、撤回和重做流程。用户项目目录无需创建 `.git`。仅在真正的 Git 项目中读取 `.git/info/exclude`，普通目录继续遵守 `.gitignore`；`snapshot: false` 配置继续生效。

产品代码只修改 `packages/ax-code/src/snapshot/index.ts`。

## 新增回归覆盖

- 非 Git 目录：原文件含 CRLF 且末尾没有换行，通过独立 Node 子进程追加中英日问候，再修复换行；撤回后按 Buffer 比较原始字节，重做后恢复编辑内容。
- 内部快照存在，用户项目没有新增 `.git`。
- 非 Git 目录：新增文件删除、被删文件恢复、忽略文件保持不变。
- 不同普通目录使用独立快照，撤回一个目录不改变另一个目录的同名文件。
- `snapshot: false` 不创建快照仓库。
- 使用真实 `SessionRevert.preview/revert/unrevert` 与数据库，验证 Git 和非 Git 两种项目中的文件内容、撤回边界、文件计数及重做后的消息记录。

会话测试构造用户/助手消息和快照补丁，不调用在线模型。子进程追加用于验证独立进程写入可以被快照捕获；未执行完整交互式 TUI/模型对话。

## 测试环境与过程

Windows，Node.js 26.8.1，Vitest 4.1.11，使用锁定依赖。先编译本地 SDK 供测试加载。测试使用项目夹具创建的临时目录及隔离数据库，没有编辑用户的 `P1/test/TEST.txt` 或真实会话数据。

修复前，新用例中四个非 Git 用例因快照为 `undefined` 失败，显式禁用快照用例通过；Git 对照用例在沙箱中遇到 `uv_os_get_passwd ENOMEM`。改用正常 Windows 用户环境执行后，修复后的六个新用例全部通过。

首次扩展回归暴露了现有测试的 Windows 兼容性问题。本次同步修正：

- 用 Node 文件系统 API 取代夹具中的 Unix `mkdir/rm`；保留带引号路径的命令解析测试。
- POSIX 权限位与制表符文件名测试仅在支持的平台执行，Windows 跳过。
- 将 `ls-files` 错误注入限定在未跟踪文件检查，避免先拦截 Windows 历史路径检查。
- 损坏快照索引测试接受 Windows 提前报错的实际检查阶段。
- TUI Redo 源码断言按操作边界截取，避免固定 1600 字符在 CRLF/文案增长后截断实际代码。

这些调整没有关闭产品侧错误检查。
