# Windows 自动升级文件占用修复报告

- 日期：2026-09-15
- Issue：[defai-digital/ax-code#453](https://github.com/defai-digital/ax-code/issues/453)
- 基线：v7.18.2，`55b0df14d304d70bae904b64fe93e8ab6d9dd4b8`
- 修复分支：`fix/windows-auto-upgrade-453`
- 结论：Windows 本地集成测试与相关回归测试通过；修复仅在该分支，尚未发布为正式版本。

## 问题与原因

7.18.2 的 PowerShell 安装器在更新前移动现有 `lib`、`node`、`node_modules`，随后激活新文件。其他 AX Code 会话仍可能持有这些目录内的文件句柄；Windows 拒绝目录移动，短暂重试无法解决持续占用。后台自动更新与手动安装共用这条安装路径。

集成测试使用真实 Windows 文件句柄禁止删除/重命名，确认旧 `node_modules` 的 `Directory.Move` 失败，然后在保持句柄打开期间执行修复后的安装器。第一次升级及下一次升级均成功，旧运行文件仍可读取，新启动器返回新版本。

## 修复

1. 对已有 Node 安装，将新包放入 `.ax-code/versions/<随机 ID>/runtime`，保留旧运行目录。
2. 在激活前检查隔离 staging、最终目录内的 Node/FFI、以及发行包原始启动器报告的版本。
3. 使用固定 `.cmd` 分发器读取 `.active-runtime`。通过同卷 `File.Replace` 原子切换指针，保留上一指针用于失败恢复。分发器直接转交发行包启动器，不使用 `CALL` 二次展开参数。
4. 首次迁移保留旧启动器第一行之后的字节偏移，用同长度跳转替换第一行，追加分发逻辑。运行中的 `cmd.exe` 在 Node 退出后仍能继续执行原来的退出语句。后续更新只替换指针。
5. 激活后验证失败时恢复上一指针；恢复失败时保留恢复文件并报告路径。已发布的分发器、旧运行目录及短暂激活的新目录均保留，避免破坏仍在运行的进程。
6. 使用独占安装锁串行化安装写入；并发安装明确失败并可重试。异常退出也会释放句柄，锁文件本身可保留。
7. 安装目录识别支持根目录及版本目录中的 `ax-code.cmd`，继续正确识别独立安装方式。

首次安装及旧原生/不完整布局仍使用原有安装事务。正式 Node 安装升级使用新路径。下载、摘要、签名校验和自动更新版本策略保持原有行为。

## Windows 实测结果

环境：Windows x64、Windows PowerShell 5.1、Node 26.8.1。测试在隔离临时安装目录中运行，复制实际 Node 可执行文件，使用真实 `cmd.exe`、文件锁和后台测试会话。

| 检查                                 | 结果                                                 |
| ------------------------------------ | ---------------------------------------------------- |
| 完整 PowerShell 安装器套件           | **59 通过**，109.66 秒                               |
| 安装布局、安装行为、自动升级策略     | **50 通过，1 跳过**；跳过项为非 Windows 符号链接测试 |
| AX Code TypeScript 类型检查          | 通过                                                 |
| SDK TypeScript 构建                  | 通过                                                 |
| 修改的 TypeScript 文件 Prettier 检查 | 通过                                                 |
| `git diff --check`                   | 通过                                                 |

新增测试覆盖：

- 旧根目录、上一代运行目录保持真实文件锁时，连续两次更新成功。
- 首次迁移时旧 CLI 会话继续运行，并在升级之后才加载旧依赖，正确退出为 0。
- 后续升级时旧版本会话继续运行、延迟加载旧依赖，正确保留非零退出码 23。
- 分发器保留带空格、`&`、`!`、`%` 的参数及退出码 17。
- 候选启动器验证、启动器替换、版本指针替换、激活后验证各阶段失败时，旧版本仍可启动。
- 指针回滚受阻时保留可定位、可使用的旧版本恢复信息。
- 并发安装拒绝第二个写入者；锁释放后可正常安装。
- Windows `.cmd` 及版本目录路径仍归属独立安装。

开发验证还发现，直接替换内容长度发生变化的 `.cmd` 会使旧会话退出码变成 123。固定分发器和首次迁移偏移兼容逻辑解决了这个问题，上述真实会话测试防止回归。

## 范围与限制

- 本次验证覆盖实际 Windows 安装事务及自动升级策略测试；没有发布未来版本，也没有以正式服务器上的新版本执行完整在线自动更新。
- 没有替换用户当前安装的 AX Code CLI，没有终止用户会话。后台会话测试只创建、结束隔离测试进程。
- 旧运行目录和恢复文件不会自动删除，因此连续升级会增加磁盘占用。清理需要在关闭相关会话后进行；完整卸载仍管理整个安装根目录。
- 目录权限、磁盘空间、启动器或指针本身的外部锁仍可能导致安装失败；此时明确报告错误。此修复消除了正常旧会话占用运行文件时必须移动这些文件的要求，不承诺绕过任意文件系统限制。
- 本地与远程 `main` 未作为修改、提交、合并或推送目标；修复和报告位于独立 worktree 的新分支。
