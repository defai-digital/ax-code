# Local fixes for three 7.15.0 boundary failures

Base: `ffa2bc321`, retaining the prior Redo correction. These changes are local only; no remote push or main-branch modification was performed.

## Corrections

### Concurrent revert consistency

Revert, unrevert, preview, and cleanup now serialize by normalized worktree path within the backend process. The queue covers planning, filesystem operations, and metadata updates. State is read after acquiring the queue position; cleanup refreshes its session instead of using a potentially stale caller snapshot. Failed operations do not poison the queue, and completed queue entries are released.

This prevents the reproduced case where two successful concurrent reverts left the first request's metadata paired with the second request's file contents. The guarantee applies to operations in the same backend process; this is not a cross-process filesystem lock or a transaction coordinating arbitrary external editors and model tool writes.

### Missing revert boundary in a capped history window

If the revert boundary cannot be found in loaded messages, the TUI hides the uncertain window instead of displaying potentially undone messages. Undo no longer guesses the newest user message. Redo returns an explicit unknown-boundary result, and the command handler shows an error instead of interpreting it as a request to restore everything. A transcript notice explains that the undo point is outside loaded history.

This is a conservative handling of incomplete history. It does not implement historical pagination or automatically load an arbitrary-size transcript. Partial undo/redo cannot safely operate from that incomplete window until the relevant history is available. Normal operations with a loaded boundary continue to work.

### RPC output EOF

The process wire now treats stdout `end` and `close` as permanent transport failure even if the child process has not exited. Pending calls fail immediately rather than waiting for the 60-second RPC timeout. Existing data handling delivers complete frames before EOF; duplicate end/close/exit notifications remain idempotent.
