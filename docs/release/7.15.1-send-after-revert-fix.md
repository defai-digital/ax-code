# Issue report: Revert 后发送消息导致历史缺失提示

## 现象与原因

AX Code 7.15.1 的会话 Revert 后发送新消息，可能出现 `The undo message is missing from stored history. Retry or use Restore all.`，并将消息隐藏。

发送新消息会提交撤销结果：后端 `SessionRevert.cleanup` 删除被撤销的历史消息并清除 `session.revert`。该动作本身正常。问题在于 `session.updated` 是完整会话快照，但前端 projection 将其当作增量合并。JSON 序列化省略已清除的可选字段，前端旧 `revert` 因此没有删除，继续查找已被后端清理的消息。

此外，删除消息事件可能先于清除撤销标记的会话更新到达，历史请求会短暂查不到边界。单纯增加加载页数或反复 Retry 无法修复残留标记。

## 修复方法

1. 对完整 `session.created/updated` 快照删除服务端已省略的字段，再原地更新属性。保留对象引用，继续使用原有的渲染性能优化。其他消息、消息片段的增量合并不变。
2. 历史加载器以 `MissingRevertMessageError` 区分“确实读到历史末尾但边界不存在”和一般网络错误。
3. 遇到该错误时重新获取权威会话状态。如果撤销标记已清除或改变，则同步新状态，不再把正常清理当成历史损坏。请求使用超时、取消及会话/边界检查，避免导航后的旧响应覆盖当前状态。
4. 若服务端仍保留相同边界，则保留原有恢复提示；刷新失败时显示可重试错误，不擅自执行 Restore all 或修改文件。
