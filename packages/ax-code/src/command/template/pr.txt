Create a GitHub pull request for the current branch using the `gh` CLI.

Input: $ARGUMENTS

If the input contains extra instructions (target base branch, title, draft status), follow them. Otherwise apply the default flow below.

---

## 1. Understand the branch state

Run these in parallel:
- `git status --short` — uncommitted changes that may need committing first
- `git log --oneline [base-branch]..HEAD` and `git diff [base-branch]...HEAD` — ALL commits and changes that will be included in the PR (not just the latest commit)
- Check whether the current branch tracks a remote and is ahead/behind

If you are on the default branch (main/master), create an appropriately named feature branch first and move the work there.

## 2. Prepare

- If there are uncommitted changes that belong in this PR, commit them first (follow the repository's commit style; never commit likely secrets).
- Push the branch to the remote with `-u` if it is not already pushed.

## 3. Create the pull request

- Analyze ALL commits included in the PR to write the summary — not just the most recent one.
- Create the PR with `gh pr create`, passing the body via HEREDOC:

```
gh pr create --title "concise title" --body "$(cat <<'EOF'
## Summary
- 1-3 bullet points describing what changed and why

## Test plan
- How this was verified
EOF
)"
```

- Return the PR URL so the user can open it.

Safety rules:
- NEVER force-push.
- NEVER push to main/master directly.
- If `gh` is not authenticated, tell the user to run `gh auth login` rather than attempting workarounds.
