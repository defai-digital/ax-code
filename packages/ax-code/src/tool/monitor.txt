Run a background shell command as a live event monitor. Matching stdout/stderr lines are recorded as session notifications and delivered to the model on the session's next model step (bounded and rate-limited). Use a selective, line-buffered command because high-rate output is throttled.

Parameters:
- command: Shell command or script. Each stdout line is an event; exit ends the watch.
- description: Short human-readable description of what is being monitored (shown in notifications).
- filter: Optional regex pattern. Only lines matching this pattern are emitted as events.
- timeout_ms: Kill the monitor after this deadline in milliseconds. Default 300000 (5 minutes). Ignored when persistent is true.
- persistent: Run for the lifetime of the session instead of a timeout. Default false.

Usage notes:
- The command should be line-buffered (e.g. `cmd | grep --line-buffered pattern`) for timely delivery.
- High-rate output (>100 lines/sec) is throttled, and recorded line batches are size-capped. Prefer filtering at the source.
- Use this for watching dev server logs, test runners, deployment status, or file watchers.
- The monitor runs in the background. This tool returns immediately with a monitor ID.
- Matching lines and the monitor's exit are recorded as notifications and delivered on the session's next model step, batched and bounded; they are not pushed instantly, and an idle session is not woken for them.
- Full output always stays available through bash_output with the monitor's shell ID.
- To stop a monitor, use kill_shell with the monitor's shell ID.
