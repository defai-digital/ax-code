Fan out a structured review or design question to multiple connected LLM providers, then aggregate agreement into consensus / strict-majority / minority / singleton findings.

**Call this tool early once the relevant evidence is available.** Supply the requirements, relevant diff, required original snippets, and verification evidence in `context`. Members only see the supplied question and context; paths do not give them file access or session history. Avoid broad repository exploration unrelated to the review scope.

Context is required evidence when supplied: at most 24000 UTF-16 code units, sent verbatim or rejected before member inference. Never cut off required evidence to fit. Split oversized reviews into explicitly scoped requests or reduce optional background. Complete prompts also undergo a conservative input-budget check including output and fallback reserves. Estimates are not tokenizer counts; unknown model limits are disclosed. A successful member response does not prove the caller included every relevant source.

Optional anonymous debate rounds (`debateRounds` or `modes.council.debateRounds`) re-share Chatham-House synthesis without member identities. Debate is capped at three rounds, stops early on convergence, and is included in the budget estimate.

Use for high-stakes architecture, security, code-quality ratings, or design trade-offs where multiple independent perspectives increase confidence. Advisory only — does not edit files.

Prefer when:
- Multi-model / council / second-opinion review
- Architecture or security with lasting blast radius
- “Good vs worse” quality findings with calibrated confidence

Avoid when:
- Only one model is available (report incomplete)
- Privacy-sensitive code must stay local-only
- Latency-sensitive trivial questions
- You only need parallel *file* digs without multi-provider ensemble → use task_parallel with explore instead (different tool)

Explicit members may use different models on the same gateway provider (for example DeepSeek and Qwen on AX Trust). Use connected provider IDs; duplicate provider/model pairs are not separate votes. Auto-selection still prefers diverse providers.
