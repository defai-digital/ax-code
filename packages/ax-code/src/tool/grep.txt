Fast content search that works with any codebase size.

Usage:
- pattern is a regular expression (ripgrep syntax): "log.*Error", "function\s+\w+".
- Braces are special in regex; escape a literal brace as \{ (e.g. "\{\}" matches "{}").
- The include parameter filters files (e.g. "*.js", "*.{ts,tsx}"); path scopes the search to a file or directory. Prefer the known file or narrowest relevant directory.
- Set context (1-10 lines before/after) to inspect definitions and callers in the same call, instead of searching then reading each hit. Adjacent context is merged; matching lines are marked with `:` and surrounding lines with `-`.
- Set limit (1-100 matching lines) to bound discovery. Defaults to 20 with context, otherwise 100. Context output also stops at 200 lines or 32 KiB and reports truncation; use Read for a complete function when needed.
- Without context, output groups matching lines by file. Context results use scan order and retain source line order within each file.
- Results are capped at limit; truncated output says so. Tighten the pattern, path, or include filter instead of paging.

Examples:
- pattern "TODO|FIXME", include "*.{ts,tsx}" — all TODO/FIXME markers in TypeScript files.
- pattern "class\s+UserService" — locate a class definition.
- pattern "contentWidth|sidebarPreferred", path "src/ui/prompt.tsx", context 5, limit 10 — inspect both symbols and their surrounding logic in one call.

There is no count mode: to count or aggregate matches, run `rg` via the Bash tool (e.g. `rg -c "pattern"`).

If a search returns "No files found", loosen the pattern or drop the include filter before concluding the code does not exist.

When you are doing an open-ended search that may require multiple rounds of globbing and grepping, use the Task tool instead.
