Open an operation plan for an infrastructure change before mutating any external state.

Use this as the first step of any cloud or network administration task (AWS, GCP, Cloudflare, OVHcloud, DigitalOcean, RunPod, VyOS, Junos). Describe the target (provider/account/region or device), the intent, every step with its effect, reversibility (reversible | hard | irreversible), and blast_radius (low | med | high), plus the exact `apply_command`. If the apply needs a state snapshot or a non-default working directory, include the exact `snapshot_command` and `cwd` now. The plan produces a canonical hash that the later `ops_approve` step pins — approval applies to exactly this command context, so args drift is rejected before token redemption.

The machine-checkable diff/plan artifact (terraform plan -out, `show | compare`, CLI dry-run output) must be produced and reviewed, then attached with `ops_diff`, before any human approval. Never skip straight to mutation: the chain is ops_plan → ops_diff → ops_approve → ops_apply.
