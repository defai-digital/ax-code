Execute an approved operation plan's mutation command — the only sanctioned path for changing external state.

Use this for the actual apply step of a cloud or network change (e.g. `terraform apply <planfile>`, commit-confirm on a device, cloud CLI mutation). Authorization is a valid `approval_token` from `ops_approve`: single-use, TTL-bound, and bound to the `plan_id` you pass. The token is redeemed before anything runs; an expired, already-consumed, or unknown token fails the call with nothing executed, and a token bound to a different plan is rejected.

Direct `bash` for mutations is discouraged — cloud/network mutating verbs are classified as destructive and gated separately. Failure does NOT refund the token: a failed or timed-out apply requires re-approval via `ops_approve` before retrying. The command's exit code and output are journaled; the raw token is never persisted.

Optionally pass `snapshot_command`: a READ-ONLY command that dumps the relevant external state so the change can be reviewed as a diff. It is executed once BEFORE the mutation and once AFTER; each output is sha256-hashed into `before_snapshot_ref` / `after_snapshot_ref` on the journal entry and in the result. The command must be strictly read-only — it runs with the same environment as the apply and must never modify state. Examples: `show configuration commands` on VyOS, `aws ec2 describe-security-groups`, `gcloud compute firewall-rules list`. A failing snapshot command does NOT abort the apply — the corresponding ref is null.
