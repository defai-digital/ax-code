# Scheduled Tasks

A scheduled task runs a prompt for you on a schedule — for example, a daily "summarize yesterday's changes" or a weekly cleanup. When it runs, AX Code starts a new session and sends the prompt on its own. Open the scheduler from the button at the top of the session sidebar.

## Create a task

1. Open the scheduled tasks dialog from the session sidebar.
2. Add a task and give it a name.
3. Choose when it runs:
   - **daily** — at one or more times each day
   - **weekly** — on chosen weekdays and times
   - **once** — a single date and time
4. Set what it does: the prompt to send, and the provider, model, and agent to use.
5. Save, and make sure the task is enabled.

Tasks are stored and run by the AX Code runtime (its `/scheduled-task` API), so they also fire when the runtime is up but the Desktop window is closed. A task with several times or weekdays is saved as one runtime task per time/weekday, named like "Cleanup (2/3)".

You can run any task immediately with **run now** to check it does what you expect.

## What success looks like

After a run, the task shows when it last ran and whether it succeeded; if a run fails, the error is shown there too. The runtime keeps a bounded run history per task, protects against overlapping runs of the same task, and automatically pauses a task after repeated consecutive failures.

## Keep in mind

Tasks only fire while the AX Code runtime is running. If it is down, missed times are coalesced into one catch-up run after restart rather than replaying every missed interval.

Tasks created by older Desktop versions are migrated automatically on first launch after the upgrade. Prompts that were slash commands (like `/review`) and cron expressions outside the runtime's supported subset are not migrated; they are recorded in the migration report (`scheduled-tasks-migrated.json` next to the per-project config directory) so you can re-create them by hand.
